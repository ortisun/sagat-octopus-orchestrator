# Claude Code

Everything above is shared with the other agents. What follows is only Claude Code specific.

- Slash commands and skills: `/speckit-*` run the specification cycle (generated by Spec Kit: do not hand-edit them, customise `.specify/templates` and the constitution); `/verify` is the pre-merge checklist; `/adr` writes a decision record; `/migration` is the checklist for a PostgreSQL migration; `/parallel-agents` is how to brief, run and merge implementer agents.
- Subagents (`.claude/agents/`, read-only): `security-reviewer`, `correctness-reviewer`, `architecture-reviewer`. Use them for an independent read before declaring a feature done; give them the diff and the spec, not your conclusion.
- Hooks (`.claude/settings.json`) enforce what prose cannot: no commit or push to `main`/`develop`, no `Co-Authored-By`, no force push, no `docker ... prune` outside the project daemon, no `cargo clean` on a shared target. Rust files are formatted after an edit. If a hook blocks you, fix the cause; do not look for a way around it.
- Context: explore with subagents or targeted reads instead of opening whole large files; plan before touching more than one crate; after a compaction re-read the active `tasks.md` and the files you are editing.
- Personal preferences go in `CLAUDE.local.md` (ignored by git). Adding one makes Claude stop reading `AGENTS.md` on its own, which is why this file imports it.
