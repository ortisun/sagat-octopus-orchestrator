## Selected observable behavior

Proposed test: `a_scanned_output_refusal_rechecks_the_original_lease_after_path_drop`.

Use an actual publicly created depth-one root ForEach with 17 compensable `line.reserve` members, Return expression `1`, concurrency 1. The report carries inline clean output, declares one genuinely managed OpenBao secret, and is scanned by the official provider. Sixteen real completions retain 4,000,000 logical bytes; the original seventeenth lease reports 250,000 bytes, so 4,250,000 exceeds 4,194,304. The secret-backed fixture at `tests/integration/workflow-primitives/refusal_secret_versions.rs:520–649` already constructs this shape with `openbao/openbao:2.7.1`, real HTTP managed-secret creation, HTTP publish/start, native scheduler ownership and public gRPC 1.5 leases/reports. Its worker registers **both** `line.reserve` and `line.release` (line594).

While the report is visibly blocked on full checkpoint restoration, publicly PUT the same worker binding to only `["line.reserve"]`. The actual report activity remains allowed and its membership stays Worker. The registered session also advertises `line.release`, so the native replacement closes that session and expires its one held lease. It preserves token, holder, status, attempt and generation. Release the gate and expect gRPC `Aborted`, machine reason `STALE_ATTEMPT`, with no report/refusal effect.

This is an expiry-only counterexample to trusting the previously checked lease. Removing the entire binding would exercise `NOT_BOUND` first and would not prove this property. No fresh-generation claim follows.

## Exact transaction and restore order

1. Scoped inline `WorkerService::complete_inner` dispatches to `report_path` (`application/src/worker/output.rs:123` onward). `checked_path_report` opens the current path, checks current authority, receipt and lease; for declared secrets it checks a live fence, obtains exact secret versions, commits, performs the actual provider scan, then reopens a current path and rechecks live fence and versions (`worker/scoped_reports.rs:230–288`).
2. `apply_path_report` reads current effective bytes while that second path transaction owns the Run lock. On overflow it retains a `RefusalCandidate`; scanned secret evidence selects `RefusalFencePolicy::Live { allow_cancellation: false }` (`scoped_reports.rs:360–399`). Returning the candidate drops its owned path transaction. `report_path` then calls `refuse_scoped_output` (`158–161`).
3. `refuse_scoped_output` calls `open`/native full `RunStore::begin` (`scoped_output_refusal.rs:32`; `worker.rs:2047–2061`). Full entry retains any applicable chain prefix, locks the Run, samples DB time after that lock, reads all step metadata, restores Run state, loads collections, loops, scope sagas and chain metadata, then resolves the pinned definition and returns the native transaction (`infra-postgres/src/execution.rs:171–267`).
4. Inside `load_collections`, the scope and iteration reads precede the exact checkpoint query (`execution.rs:1888–1947`). The selected gate blocks this query **after the full transaction owns the Run and has already read step attempt/generation/status metadata**, but before full current binding/role/receipt/lease checks. The earlier path reader does not read `iteration_checkpoints` for this fixture. Its budget helper sees no successful root collection requiring overlay verification. Arrival at this full-only query establishes that the checked path completed, chose overflow, and released its lock.
5. After full entry returns, current identity/definition then current binding/membership and exact receipt are checked; `verify` checks current token/status; `strict_refusal_fence` checks original attempt/generation/cancellation/terminal facts and, for Live, issues the native current lease-expiry query. Exact scanned versions and budget are checked only after that (`scoped_output_refusal.rs:33–67,177–209`).
6. `lease_matches_instance` requires exact path/node, LEASED/RUNNING and token but does not check expiry (`execution.rs:3968–3987`). `lease_unexpired_instance` adds `lease_expires_at > clock_timestamp()` in a new read on the same transaction (`3815–3835`). Thus the original matching token can pass `verify`, while the new expiry fails the required live check. It does not reuse the pre-barrier `tx.now()` or the previously checked path expiry.

## Why this authorized mutation can win at this gate

`BindingStore::replace_binding` retains the worker binding advisory lock, replaces the requested patterns, locks the subject's sessions, and closes precisely those whose complete advertised activities are no longer covered (`infra-postgres/src/bindings.rs:77–181`). It updates their currently LEASED/RUNNING steps with native `lease_expires_at=clock_timestamp()` and removes sessions. It takes no Run row lock and reads no checkpoint table. Full restoration only read the step rows, without retaining a conflicting step row lock. The preceding path's authority guards are gone, and full authority checks have not yet acquired them. This makes binding narrowing viable even with the Run lock already held; actual completion within the timeout must prove it in the test.

By contrast, real worker completion/failure, scheduler expiry/reclaim and run cancellation serialize on that Run. They cannot commit a changed generation or terminal scope while this checkpoint barrier holds. Queuing one and assuming it wins after gate release would depend on scheduling/FIFO and is not a valid test design. No such claim is selected.

Current full `ensure_bound` checks current task activity and WorkerExecute membership (`worker.rs:2202–2255`), not session existence. The ordinary report wire does not depend on replaying the deleted registration session. Keeping `line.reserve` and the membership means the narrowing cannot correctly produce NOT_BOUND/FORBIDDEN/UNAUTHENTICATED. A missing receipt and unchanged real identity/token/attempt/generation, clean secret catalog, no cancellation and nonterminal state discriminate the intended `STALE_ATTEMPT`.
