# 0.3.0

This release closes feature 014 on root (unnested) collections and loops, with published ceilings
of 1,000 items and 1,000 iterations, and adds the first delivery of compensation safety (feature
037), Redis Streams as an alternative hint transport (033) and the official Rust SDK (034). Feature
018 schedules and the feature 035 Iceberg connection and probe are built and ship turned off. The
claim and report path was made cheaper (design 038). Nested collections are not in this release; they
are feature 039. Feature 037 changes how the engine handles an uncertain external effect, and that
change is breaking.

Release gates: the whole stack passed on the release candidate `a4f6e9db` (CI run 43467642086, 14 of 14 jobs).

## Workflow primitives: root collections and loops (feature 014)

`forEach` collections, loops, approval, `switch`, declared Query/Update and the restricted
continue-as-new are released for root (unnested) use. Since 0.2.0 a collection body may start at,
or route to, a condition, switch, timer or `waitEvent` node. Such an entry runs in the scheduler
and takes no worker lease. A scoped event wait reads the captured `item`, `index` and local
outputs, may use `lookbackMs`, and drains and compensates the collection on an unhandled timeout.
An explicit `iteration_concurrency` policy of zero stops new admission and lets accepted work finish.

Evidence (T014-040, root scope): fault 92/92 (also as `sagat_app`), integration 762/762 with 22
ignored, contract 49/49, e2e 1/1, on PostgreSQL 18.6. The 20 collection and loop conformance
scenarios pass in all six SDKs without bless. The 10,000-item case at width 256 passed as a
diagnostic in 704 s. That run used a debug build on a shared laptop, so it is not an acceptance run.

Not released: nesting (feature 039), triggers and broader structured combinations. The ChildRoot
worker-lease guard stays off and has no operator switch (OD-2026-11-04-3). The capacity Vacate
adapter and its transfer-receipt table have no production caller. Children and approvals inside
collection bodies remain closed. See [workflow primitives](../runbooks/workflow-primitives.md).

## Compensation safety, delivery 1 (feature 037)

Under Constitution principle III, an attempt whose outcome is unknown now waits for a person in
every activity, and the engine no longer retries it. The behaviour changes are listed under Breaking
changes. Journals written by v0.1 and v0.2 replay with their original meaning, and in-flight runs
continue after an in-place upgrade. The delivery adds no migration and no wire change.

Not included: provider qualification for uncertain effects (US04, T037-032 and T037-033 are open).
An ordinary `SECRET_IN_OUTPUT` keeps the feature-009 final-failure behaviour and is not sent to the
review queue. See [sagas](../runbooks/sagas.md), [draining workers](../runbooks/scaling.md#draining-workers-before-a-restart)
and [ADR-0076](../adr/ADR-0076-compensation-failure-and-uncertain-effects.md).

## Redis Streams (feature 033)

To send internal `task.ready` and `run.finished` hints through Redis instead of NATS, set
`SAGAT_EVENT_TRANSPORT=redis` and `SAGAT_REDIS_URL`. Optional settings are `SAGAT_REDIS_STREAM`,
`SAGAT_REDIS_STREAM_MAXLEN` (default 100,000) and `SAGAT_REDIS_TIMEOUT_SECS` (default 5). If
`SAGAT_EVENT_TRANSPORT` is unset, the legacy optional NATS configuration applies. PostgreSQL stays
authoritative and workers still claim over gRPC. Redis may append a duplicate entry, so deduplicate
by `message-id`. Changing the transport is a cold cutover. Mixed NATS and Redis dispatchers are not
supported.

Redis callback destinations (`kind: "REDIS"` on broker subscriptions) are off until
`SAGAT_REDIS_CALLBACKS_ENABLED=true`. Set it only after every old control plane and engine is
upgraded or stopped. Helm needs explicit `networkPolicy.egress.redis` peers. See
[events](../runbooks/events.md#redis-streams-v03) and
[ADR-0069](../adr/ADR-0069-redis-streams-share-outbox-and-delivery-authority.md).

## Rust SDK (feature 034)

The Rust SDK is now an official SDK. It has typed REST clients, a Tokio worker host, workflow
builders that emit the canonical IR, and secret, blob, scoped and compensation capabilities. It
passes the shared conformance and fault suites with the other five SDKs. See
[SDK packaging](../runbooks/sdk-packaging.md#rust-crate-candidate), [compatibility](../sdk-compatibility.md) and
[ADR-0070](../adr/ADR-0070-rust-sdk-shares-the-canonical-sdk-contract.md).

## Schedules (feature 018), built and turned off

Schedules are first-class namespace resources. They can be created, revised, deleted, paused,
resumed and triggered on demand, and can be backfilled under overlap and catch-up policies. Runs
record which schedule started them. The REST routes and the engine pass exist only with
`SAGAT_SCHEDULES_ENABLED=true` on both the control plane and the engine. The default is off. The
batch tuning settings are `SAGAT_SCHEDULES_BATCH` and `SAGAT_SCHEDULES_POLL_MS`. The routes are in
the OpenAPI contract.

Schedules are **experimental** in 0.3.0: there is no operator runbook yet, the routes and settings
may change in a minor release, and 19 of the 81 tasks of feature 018 are done. Leave the setting off
in production.

## Iceberg connections and the lake runner (feature 035), built and turned off

The lake is off unless `SAGAT_LAKE_ENABLED=true` is set on the control plane and on the process that
serves the worker gRPC. While it is off, publishing a workflow that holds an Iceberg write is refused
with `LAKE_DISABLED`. While it is on, an administrator can save an Iceberg connection (REST catalog over
S3-compatible storage), create its OpenBao secrets in Studio, and probe it with
`sagat.database.lake.probe` on a database runner configured with a `lake` section. Bindings carry
a profile (`database` or `lake`). A plain-http address other than the loopback is refused when saved.
The worker protocol adds the Iceberg, object-storage and ClickHouse connection messages as new fields.

Writing to a table from a workflow is not usable yet. The runbook says
"do not rely on it to write to a table yet", and the append path (T035-057, T035-059), the example
and e2e test (T035-062), and the rollout setting T035-036 are open. Catalog browsing
(`/catalog-browse`) is in the contract as `x-planned` and has no route. Overwrite, upsert,
step-output destinations, Glue, Hive, JDBC, GCS and ADLS are not built. 20 of 129 tasks are ticked.
See [the Iceberg connection guide](../guides/iceberg-connections.md) and
[database runner](../runbooks/database-runner.md).

## Claim and transition cost (design 038, bugfix PR 203)

Worker reports and claims no longer serialise on advisory-lock mutexes. A poll stops at the first
candidate the session cannot take, skips projection loads and rewrites of `node_kind` that change
nothing, and tries the shared window from a per-session offset. A pull request that changes these hot-path files now runs a
budget test of the statements per lease and per completion (Constitution 4.4.0). Measured on
2026-11-12 on a loaded machine, the best figure was 1,026 transitions per second, against 1,513 on
2026-10-11. With few workers, the rate is 57% to 68% of the October figure.
See [the report](../../tests/performance/reports/scalability-ha.md).

## Maintenance

Dependency and advisory updates: PRs 55, 79, 82, 83, 108 and 217. Test flakes fixed: PRs 80, 81, 99,
107 and 110. Development process: Spec Kit was replaced by the EGM design cycle (Constitution 4.0.0
to 4.4.0). A pull request now runs only the tests of what it changes, the full stack runs for a

## Breaking changes

1. **Uncertain external effects wait for a person (037).** This applies only to decisions made after
   the upgrade.
   - An unknown outcome (lost lease, `ATTEMPT_TIMEOUT`, `OUTCOME_UNKNOWN`) creates a review item in
     any activity, and `highRisk` no longer changes this.
   - A lookup that answers `not_applied` no longer retries. The step waits with `RECONCILIATION_NOT_FINAL`.
   - `RETRY_STEP` on an unknown outcome returns 409 with `details.reason` `OUTCOME_UNRESOLVED` for
     every role, administrators included.
   - Compensation is planned only for a succeeded effect, and defensive compensation is removed.
   - Cancellation and deadlines keep a pending review. `COMPENSATION_FAILED` waits for independent
     compensations to settle.
   - A stored-output refusal is `STORAGE_QUOTA_EXCEEDED` instead of `RUN_DATA_LIMIT`.

   **Clients must** call `RESOLVE_STEP` after checking with the provider instead of `RETRY_STEP`, handle
   the new 409 and codes, and drain workers before a restart, because a stopped worker with in-flight
   activities now creates review items.
2. **Development process (no product effect).** The `/speckit-*` commands and `.specify` are removed.
   The constitution is at `docs/constitution.md`. CI no longer runs on merges into `develop`.

No REST path was removed. The worker protocol stays at 1.6 and its changes are additive. The event-read
change of 0.2.0 (event detail values need an explicit reveal) is unchanged.

## Limits

| Limit | 0.3.0 | Source |
|---|---|---|
| `maxItems` of a collection | published 1,000; validation accepts 1 to 10,000 | OD-2026-11-04-5, OD-2026-11-13-1 |
| `maxIterations` of a loop | published 1,000; validation accepts 1 to 10,000 | OD-2026-11-04-5, OD-2026-11-13-1 |
| `maxConcurrency` of a collection | 1 to 256, bounded by the tenant's `iteration_concurrency` quota | `crates/domain/src/workflow.rs` |
| Pending waits (approvals, timers, event waits) | 20,000 per scheduler replica at the 500 ms default interval | OD-2026-11-04-6 (delegate) |
| Nesting of collections | refused by the codec | feature 039, OD-2026-11-12-6 |

The 1,000 values ship without the T014-042 acceptance run, which needs a separate database host.
Raising them to 10,000 is deferred until that run passes. A collection's real bound is the smaller of
`maxItems` and what the tenant quotas allow, so raise a quota rather than the ceiling.

The wait ceiling is watched by `scheduler_waits_per_replica`, `scheduler_pending_waits` and
`scheduler_tick_seconds`, with the alerts `SagatSchedulerWaitsPerReplica` (above 16,000 for 15
minutes) and `SagatSchedulerTickSlow` (95th percentile tick above 0.5 s for 10 minutes). See
[scaling](../runbooks/scaling.md#scheduler-waits-per-replica) and
[observability](../runbooks/observability.md).

## Upgrade

Follow the 0.2.0 procedure:

1. Back up and test the upgrade on a restored copy.
2. Stop admissions and every writer.
3. Run migrations once as the database owner.
4. Deploy compatible engines, workers, readers and Studio.
5. Resume admissions.

Do not run old and new engines side by side, and drain workers first.

Sixteen migrations were added (`20261221000000` to `20270112000000`, each with a down file).
Five of them need care on a large database:

- `20261223000000_event_lookback_cursor` creates an index on `steps`.
- `20261225000000_capacity_discovery_index` and `20261231000000_capacity_worker_membership_indexes`
  create indexes on the capacity tables.
- `20261230000200_schedule_run_provenance` adds four nullable columns, three CHECK constraints and an
  index to `runs`. The constraints are added `NOT VALID` and validated afterwards.
- `20270110000000_step_credential_roles` replaces the primary key of `step_database_credentials`.

None of these indexes is built `CONCURRENTLY`.

Some down migrations refuse while data depends on them: `20261221000000`, the transfer receipts of
`20261226000000`, and the lake blob pins of `20270111000000`. The runbooks give the order to follow.

How long these index builds lock a production-sized table was not measured: schedule the migration in the
maintenance window of step 2 and test it on the restored copy of step 1.

- **Worker protocol:** 1.6. Root work needs at least 1.4, scoped work 1.5, and database runners 1.6.
- **SDKs:** all six packages (TypeScript, Go, Python, .NET, Java, Rust) are 0.3.0 and default to
  worker protocol 1.5. They are GitHub Release assets; Go is the module tag `sdks/go/v0.3.0`.
- **Released-v0.2 compatibility:** tested upgrades from v0.2 cover:
  - a v0.2 public producer through the current migration and released readers;
  - a released worker that keeps its scoped request across an upgrade;
  - the cutover of the released callback publisher to Redis (033).

  The released-source profiles passed in the CI job "released v0.2 upgrade compatibility" of the
  release-candidate run. See
  [workflow primitives](../runbooks/workflow-primitives.md#verify-the-released-v02-active-data-upgrade).

## Not in this release

- Nested collections, the capacity program they need (sweeper, creator, `SCOPED_PATH`, G715, G724,
  G725) and the nested 100,000-instance workload are feature 039. They need ADR-0078 accepted
  ([design](../designs/039-nested-collections.md)).
- The 10,000 ceilings and the T014-042 separate-host acceptance run.
- Drafts 019 to 032 and 036. The owner approved them for implementation (OD-2026-11-11-1), but none
  is built. 036 merged its specification only.
- Feature 018 parts in open draft PRs 91 (batch operations, Studio schedules, pass metrics) and 98
  (business ids, start delay, with-start, reset, run provenance, CLI and SDK builders).
- Merged but off: schedules (`SAGAT_SCHEDULES_ENABLED`), the lake and Iceberg connections
  (`SAGAT_LAKE_ENABLED`), Redis callbacks (`SAGAT_REDIS_CALLBACKS_ENABLED`) and the ChildRoot guard.
  Iceberg writes, catalog browsing and destinations are not usable.
- Provider qualification for uncertain effects (037 US04).
