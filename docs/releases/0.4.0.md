# Sagat Octopus Orchestrator 0.4.0

These notes belong to the earlier release-number scheme, superseded by the maintainer’s reset
recorded in [0.1.0](0.1.0.md). They are retained as historical context and are not current
installation or upgrade instructions. Use [0.2.0](0.2.0.md) and the current runbooks. Availability
of old artifacts is not asserted here.

This release integrates the completed platform foundation, inline-code sandbox, Workflow Studio,
security and multitenancy, scalability and recovery, and developer-experience work from `develop`.

## Changes

- Isolated C# compilation and execution with pinned .NET images, curated offline NuGet dependencies,
  dependency evidence and shared sandbox contracts. TypeScript and Python artifact compatibility is retained.
- Durable sandbox-denial incidents with tenant, principal and lease fencing. Acknowledgement follows
  the database commit; incident categories exclude destination URLs and other sensitive payloads.
- Role-specific Kubernetes ingress and egress policies with explicit peers and fail-closed validation.
  Sandbox network policy reloads fail closed when policy cannot be read.
- Scheduler sharding, tenant fairness, bounded connection use, worker scaling configuration and
  reproducible recovery and load drills.
- Owner-approved Studio interfaces and completed CLI, examples, onboarding and API-reference work.
- Shared protocol conformance coverage for TypeScript, Go, Python, C# and Java SDKs.

- Maintained YAML parser for CLI manifests and contract tooling, removing the unmaintained
  `unsafe-libyaml` dependency without adding an audit exception.

## Historical upgrade guidance

The former 0.3.x/0.4.0 upgrade and independent-SDK-version instructions are superseded. Follow
[0.2.0](0.2.0.md), [scaling](../runbooks/scaling.md) and the coordinated security/OpenBao recovery
runbooks. Explicit, fail-closed NetworkPolicy dependency peers remain mandatory.

## Validation and limits

These are the historical limits of the tagged release checkpoint. Subsequent completion work
on this branch adds isolated Go/Java runners and a measured single-node full-product/KEDA
deployment; see the current [traceability record](../traceability.md). Those later results do
not change what was validated in the original tag.

The release PR runs the full CI suite: Rust formatting, Clippy and tests; architecture checks; all five
SDKs and conformance journeys; Studio unit and browser tests; contracts; Docker Compose smoke;
observability configuration; scale/recovery drills; and dependency audits.

Security evidence includes Cilium allow/deny tests on fresh and existing clusters using controlled TCP
canaries and restricted workload specifications. This does not establish a complete Helm application
rollout, KEDA operation, or PostgreSQL/OIDC protocol behavior in Kubernetes.

The documented 5,000-transition-per-second target, partitioned journal, asynchronous-standby RPO and
human newcomer study remain unproven. Inline Go and Java execution is not implemented. See the
[traceability record](../traceability.md) and feature quickstarts for measured results and remaining gaps.
External effects still require idempotency or reconciliation; this release makes no exactly-once promise.

The historical numbering does not identify a currently available release artifact. Consult the
current tagged release and its artifact manifest; publication does not deploy an environment.
