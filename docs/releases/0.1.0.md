# Sagat Octopus Orchestrator 0.1.0

The maintainer selected 0.1.0 for this delivery. This resets the product release number; it does
not roll back the implementation or database schema. At the maintainer’s request, v0.1.0 replaces
the old v0.4.0 tag; the older validation record remains documented in Git history. Use an explicit source tag or image version rather than assuming numeric
version order identifies the newer implementation.

## Included

- Durable workflows, sagas, tenant quotas, recovery and audited namespace management.
- Studio namespace and integration menus, workflow/script authoring, trace links, signals and
  operational worker drain/resume controls.
- Isolated TypeScript, Python, C#, Go and Java script execution; durable NATS/Kafka/SQS delivery.
- Five SDKs with blob support, OpenTelemetry and finite-credit task streaming.
- README instructions for installation, configuration, scripts, validation, troubleshooting,
  access ports, Docker and Kubernetes.

Rust workspace packages, Studio, the E2E package, Helm chart/application and OpenAPI document
metadata use 0.1.0. SDK package versions are already 0.1.0. The worker wire protocol remains 1.4;
REST routes remain /v1. Release numbering does not change protocol compatibility.

## Installation and migration

Build from this checkout using the [README](../../README.md). SDK registry publication and
container image publication are not implied by a source release.

Existing installations retain their database. Back up first and apply all pending migrations as
the database owner. Migration 20261026000000 activates durable byte enforcement and requires a
coordinated writer upgrade. Retain the additive schema on rollback; do not run down migrations
automatically. See [control-plane operations](../runbooks/control-plane.md) and
[scaling](../runbooks/scaling.md) for configuration and migration constraints.

The Helm chart requires explicit NetworkPolicy dependency peers. Render it with installation
values before applying it. When replacing a historical 0.4.0 installation, select this version
explicitly; its smaller version number is intentional and does not describe a code downgrade.

## Validation and limits

The implementation checkpoint before this metadata adjustment passed all 11 platform CI jobs,
2,255 Rust tests, 1,105 Studio tests, five-language SDK conformance and package installation.
The release PR records validation for the final version and dependency integration separately.

Public SDK registry publication still requires owner identities and credentials. Genuine human
usability acceptance, production-scale throughput and multi-node/zone recovery remain unproven.
The recorded Kubernetes/KEDA experiment used one node. See [traceability](../traceability.md).
External effects remain at-least-once and require idempotency or reconciliation.
