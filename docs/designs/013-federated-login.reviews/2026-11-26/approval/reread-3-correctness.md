Counts: Blocker 0, Major 0, Nit 8

1. **Nit. Technical Plan 4, "Before the transaction"; Technical Plan 12.** "Still unknown after a successful re-read is `invalid_grant`" can hit a usable token: after a `revoke`, or a read whose freshness is taken at completion, a replica that spent its re-read refuses a new-key token as `invalid_grant`, against Requirement 013-026. Fix: key ids are monotonic; an unknown id newer than the newest known, when the re-read is suppressed or the last read started before the request, gets `503 IDENTITY_SIGNING_UNAVAILABLE` with the token unspent; `invalid_grant` only for older ids or after a read that started after the request; freshness taken at the start of the read; a test.
2. **Nit. Technical Plan 12, `rotate`.** A resuming `rotate` compares the stored time with its own clock, so clock skew can promote at once. Fix: wait two intervals on the resuming machine's monotonic clock from when it first reads the `PENDING` key; drive `a_second_rotate_finishes_an_interrupted_rotation` with a skewed clock.
3. **Nit. Technical Plan 2, `RefreshTokenMac`.** `handle(key_id)` fits only the refresh grant: redemption has no key id and only mints, logout must verify against a stale ring, and logout's answer for an unknown id whose re-read fails is unstated. Fix: a minting handle for redemption, a verify-only handle for logout that ignores staleness, logout with an unknown id after a failed read answers `503` (the client keeps the entry), a named test.
4. **Nit. Technical Plan 4, "Rate limit and answers".** The answer to a fourth grace rotation within the window is unstated. Fix: a fourth grace use is a reuse that revokes the session, audited; `a_fourth_grace_rotation_revokes_the_session`.
5. **Nit. Technical Plan 4, "Grace and retirement".** `two_concurrent_refreshes_keep_the_session` asserts the other is refused, but its use revokes the session. Fix: assert the kept token refreshes, then that the retired token is refused and the session revoked, and rename the test.
6. **Nit. Technical Plan 4, "Verification order and locking", against "Lock order".** The refresh grant and logout are missing from the lock order and `lock_order.rs`; if they lock a connection or membership row they invert redemption's order. Fix: they lock only the session row and its grace rows and read the connection and membership without locks; both paths in `tests/support/lock_order.rs`.
7. **Nit. Technical Plan 12, the background task.** The per-request re-read of a stale ring has no per-interval budget, so in an outage every request waits on an OpenBao timeout. Fix: share the per-interval budget; after a failed read within the interval, answer `503` at once; a test counting the reads.
8. **Nit. Technical Plan 12, `identity attempt-key rotate`.** The attempt ring promotes after one interval and nothing re-reads on an unknown attempt key id, so a replica whose read failed cannot open a new sign-in. Fix: promote after two intervals or re-read on an unknown id; include a replica whose last read failed in `an_attempt_sealed_after_a_rotation_opens_on_every_replica`.
