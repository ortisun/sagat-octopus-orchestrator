**Paraphrase (summary).** Each tenant signs its people in through up to eight OIDC or SAML connections, configured by an administrator with `identity:manage`; the control plane brokers, issuing five-minute ES256 tokens whose tenant comes from the connection. People arrive just in time (`federated:<uuid>`, never `admin`) or by SCIM, whose deactivation suspends and revokes in one transaction; SCIM groups become rows of feature 029's `access_groups`. A sign-in begins at `GET /v1/auth/authorize`, is bound to the browser by `__Host-sagat_login`, returns a one-use code from the callback, and is redeemed with PKCE at `POST /v1/auth/token`, which creates the session; the Studio renews by cookie, the CLI rotates its refresh token, and every request joins the session into the membership read. Four milestones; domains, assertion groups, Transit, back-channel logout, encrypted assertions, a development SAML provider, the `apps` client and live commercial runs are deferred.

1. **Blocker. CUJ 1; Requirements 013-001, 013-011, 013-012; Technical Plan 13 "Linking".** The test sign-in that activates every connection is the link flow, which "starts from an authenticated Studio session" and confirms with the renewal cookie; an administrator signed in through the deployment issuer has a bearer token and no session cookie. How her subject is recorded on a top-level navigation, which cookie the confirmation checks, whether a link callback issues a code, and what "no session usable for the API" means are not said. Fix: a numbered "Test sign-in and link" flow (a bearer-authenticated start returning a one-time address, no code on the callback, the confirmation's authentication for both kinds of user, no session row), cited by CUJ 1.
2. **Major. Overview; Architecture decision 0140 decision 8.** The Overview says `apps/dev-idp` gains a development SAML provider, which Decision 013-010 removed. Fix both.
3. **Major. Requirement 013-027.** "Sign-in by organization or e-mail" contradicts the deferral of e-mail discovery. Fix: organization, with an optional e-mail as `login_hint`.
4. **Major. Technical Plan 4 "Complete", Technical Plan 3.** The callback "records … its groups", yet no group comes from an assertion and no column holds them. Fix: delete it.
5. **Major. Requirements 013-019, 013-021; Technical Plans 4 and 10.** "The silent path" and "a silent sign-in" are undefined and overlap with renewal. Fix: define the trigger, or remove the path if renewal covers every case.
6. **Major. Requirement 013-018; Technical Plans 4 and 7.** One session cookie per browser is an unstated limit, and "the Studio asks the person first" has no mechanism (the cookie is `HttpOnly`); server or Studio enforcement is not said. Fix: state the limit and a mechanism, for example a typed refusal unless a replace flag is sent.
7. **Major. Technical Plans 4 and 13.** The redemption's order is spread over three places that disagree (the code consumed then marked again, the session and code "after" the membership, the advisory lock "first"); whether the code consumption is inside the transaction is unclear; "slot" is never explained. Fix: one numbered list with each lock and slot; one transaction; the code marked once; link and gloss Architecture decision 0050.
8. **Major. Requirement 013-019, Non-functional requirement 013-001.** "Re-check at most every 10 seconds" reads as a frequency cap, the opposite of the guarantee. Fix: "at least once every 10 seconds".
9. **Major. Requirement 013-026.** The 30-second grace refuses the lost-response case, leaving the CLI with no usable token, so `a_lost_refresh_response_keeps_the_session` misleads, and the CLI's recovery is not said. Fix: return a successor within the grace, or keep the refusal, state the recovery and rename the test.
10. **Major. Technical Plans 3 and 13; Requirement 013-021.** The identity-settings row that every path locks exists only "for a tenant that sets them", and `federated_only` lives on `tenants`; the lockout argument needs the row to exist. Fix: the row always exists; say which row a federated-only change writes and locks, or move the flag onto it.
11. **Major. Technical Plan 12 "Rollback".** It tells the operator to wait for "deployment-issuer identities linked", a mechanism the design forbids. Fix: state the real consequence and the real way back.
12. **Major. Requirements 013-001, 013-020; Technical Plans 2 and 11.** The administration routes are never listed; `/auth/sessions` may be the sign-in service's or the REST API's; whether `membership:manage` exists and who holds it is not said. Fix: a route table with full prefixes and permissions; state the permission's status.
13. **Major. Requirement 013-025; Technical Plan 4; Architecture decision 0140 decision 7.** The publication time of a new key is one interval in one place and two in others; the interval and the leeway have no value; whether the command waits is not said; the retention clock is unclear. Fix: values once, "two intervals" everywhere, how the command waits, retention from the successor's activation.
14. **Major. Throughout.** Load-bearing terms cited by number without a link or gloss: slots, the access fence, the instance registry and its gate, beat and epoch, the intent-write-verify-activate protocol, Architecture decision 0143 decision 2, the battery and the canary scan, the test composition and the development overlay, reveal grants, secret access entries and feature 026 links. Fix: a link and a clause of gloss at first use.
15. **Nit. Technical Plan 13, Task 013-9, Requirement 013-012.** Leftovers of the deferred domains: `DOMAIN_CLAIMED`, a test named for "discovery", "Entra ID's `email` claim never at all". Fix: remove, rename.
16. **Nit. Technical Plan 13 against Task 013-5.** "Two plain reads" against "three", neither named. Fix: name them, one count.
