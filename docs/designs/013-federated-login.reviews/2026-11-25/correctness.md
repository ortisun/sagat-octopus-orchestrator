1. **Blocker. Technical Plan 3, Task 013-4, against Technical Plan 4 (Verify).** `Subject::parse` also reads stored subjects back (`IdentityService::authenticate`, `membership_from_row`, schedule `authorizedBy` and backfill readers, approvals, published-by and receipt readers, reveal grants, worker sessions, the IR approver conversion), so reserving `federated:` there makes every federated member unable to authenticate, fire a schedule, be named as approver, or be read back without a 500. The named test passes regardless. Fix: do not reserve the prefix in `Subject::parse`; refuse it only in `authenticate_bearer` for deployment-issuer tokens; red test that a platform token for `federated:<uuid>` authenticates and a schedule it authorized fires. Confirmed in code.

2. **Major. Technical Plan 6 (Role mapping), Requirement 013-013, the redefinition of `sagat_lock_memberships`.** The fallback from an expired assertion-mapped role exists only in the per-request read; `sagat_lock_memberships` and the two plain reads return the stored `m.role` to eleven re-check callers, so a schedule or a managed-secret write acts with the expired role; the tidy pass, selecting by expiry, can overwrite a fresh role committed by a sign-in. Fix: one SQL expression of the effective role shared by `sagat_lock_memberships`, the plain reads and `find_membership` (a definer function); the pass a conditional `UPDATE ... WHERE mapped_source = 'ASSERTION' AND mapped_expiry < now()` under the row lock and the lease fence; a red test per caller family. Confirmed in code.

3. **Major. Technical Plan 6 (Assertion groups), Architecture decision 0142 decision 4, the group-source contract, 029 `data-model.md`.** "Confers nothing once the session that wrote it ends" has no mechanism: revocation and idle expiry update no timestamp of the rows, and 029's evaluator joins no session; two sessions through one connection are undefined. Fix: store the writing `sid` on assertion rows and the mapped-role source, join live sessions in the evaluator's membership query and the effective-role expression, state the multi-session rule; or drop "when the session ends". Confirmed in the documents.

4. **Major. Requirement 013-013, FR-029-024, the contract's guarantee 6, the 029 readiness note.** FR-029-024 removes group memberships on any built-in role change, so a mapped role change deletes the membership that caused it; even with external memberships kept, an assertion-mapped role changes at every expiry and sign-in, each change wiping direct assignments, folder entries and reveal grants (`20261220000000_reveal_grants_role_change`), so "a directory cannot make it flap" is false. Fix: amend FR-029-024 to exclude external memberships; decide whether an expiry fallback counts as a role change (compute it and never store it, or state the revocation); a test that a direct assignment survives two sign-ins with the same groups. Confirmed in the documents.

5. **Major. Technical Plan 6, Requirement 013-013.** Editing the rules or the default never recomputes: a deleted `admins -> admin` rule leaves administrators until their group next changes; a rule below the default lets the expiry fallback raise the role. Fix: a rule or default change recomputes every member the connection owns, in its transaction or a bounded audited job in subject order; state the rule-below-default case; `a_removed_admin_rule_demotes_its_members`. Confirmed in the documents.

6. **Major. Technical Plan 4 (Redeem, Lock order), `signin_codes`.** The code is locked after the membership, so two concurrent redemptions both see no identity and the loser's unique violation maps to a 500 (`classify`, `crates/infra-postgres/src/identity.rs`); signing after commit lets an OpenBao failure spend the code, and the retry then revokes the session. Fix: consume the code first by a conditional `UPDATE ... RETURNING` (slot 2), revoking the produced session when no row comes back; then the membership; sign before commit (an uncommitted `sid` is refused by the join); a barrier test. Error mapping confirmed in code; the race plausible.

7. **Major. Technical Plan 3 (grants), Technical Plans 4 and 6.** `sagat_app` has only `SELECT` on `memberships`, deliberately ("The runtime deliberately cannot change memberships"), yet just-in-time inserts, SCIM, mapping, the member routes and the pass write it; a plain `UPDATE` grant would let any injection promote to `admin`, reversing a least-privilege property. Fix: writes through narrow `SECURITY DEFINER` functions (insert member, set status, set mapped role, delete member) with their predicates and audit; a grant table; `runtime_privileges` failing if `sagat_app` gains `UPDATE` on `memberships`. Confirmed in code.

8. **Major. Technical Plan 4 (Lock order).** The lock strength is unstated; two redemptions holding `FOR SHARE` and then updating the role deadlock; the session, token and connection ceilings are counted without a lock; an ownership change races an old owner's SCIM. Fix: `FOR NO KEY UPDATE` through the definer functions for every writer; re-check status and ownership after the lock; count ceilings under the membership or connection lock; the double-redemption case in the slot tests. Plausible.

9. **Major. Requirements 013-001, 013-010, 013-019, Technical Plan 4.** A redemption that read the connection active commits its session after a disable's revoking `UPDATE`, so a disabled connection leaves a live session; the same for a raised context and SCIM. Fix: redemption, refresh, renewal and SCIM take the connection row `FOR SHARE` before the membership and re-check after the lock, or the per-request statement joins the connection's state; a barrier test. Plausible.

10. **Major. Requirements 013-021 and 013-001.** Write skew: enabling federated-only and disabling the only active connection, or resetting two active connections at once, both pass under read committed. Fix: every check-and-change of federated-only, connection state and reset takes the tenant's identity-settings row `FOR UPDATE` first; barrier tests. Plausible.

11. **Major. Technical Plans 4 and 6 (SCIM).** A SCIM transaction reads a group's members to know which memberships to lock, before any lock; a concurrent `PATCH` adding a member can be undone by a `PUT` without recomputing that member's role (`If-Match` is not sent by Okta or Entra ID). Fix: read `generation`, lock, re-read it and retry if it moved, or a per-group advisory lock recorded as a deviation; a barrier test. Plausible.

12. **Major. Requirements 013-015, 013-016, Technical Plan 3 (`external_identities`).** A SCIM `POST` racing a first just-in-time sign-in for one person ends in a 500; adoption of a person who already signed in is unstated; after a SCIM delete the kept deprovisioned identity blocks a new one under the unique key, and reuse of the old subject would re-attach old schedules and policies. Fix: a transaction advisory lock on (tenant, connection, provider subject) before resolving; state adoption and re-provisioning; map the constraint to a typed conflict or SCIM `uniqueness`. Plausible.

13. **Major. Decision 013-017 against 029's `UNIQUE (tenant_id, name)` on `access_groups`.** An external group named like a local one (or like another connection's) violates the key; an assertion value equal to a local group's name makes the sign-in fail. Fix: unique name among `LOCAL` rows only (a partial index), unique (tenant, connection, `external_value`) for external rows; amend 029's data model. Confirmed in the documents.

14. **Major. Requirement 013-026, Technical Plan 4.** Refresh-token reuse detection logs users out in ordinary cases: two CLI processes refreshing at once, a lost refresh response, a signature failing after the rotation committed. Fix: rotate by compare-and-set on `generation`; sign before commit; within a short grace window answer a reuse of the immediately previous generation without revoking; the CLI holds a file lock around a refresh; tests for both cases. Plausible.

15. **Major. Requirement 013-016, Architecture decision 0142 decision 6.** The requirement both revokes app sessions in the deactivation's transaction and says a deactivation writes no app-session row, and the record still requires the write, which recreates the slot-1 cycle; the cross-reference points to the wrong section. Fix: drop the app-session revocation from both; app sessions check the membership read and `signin_sessions`; fix the reference. Confirmed in the documents.

16. **Major. Non-functional requirement 013-001, Requirement 013-019, `routes/execution.rs`, `streams.rs`.** Run streams re-check every 30 seconds by `authenticate(tenant, subject)` without `sid`, so a revoked session's stream runs to its token deadline, and 30 seconds exceeds the release-blocking 15 seconds left from the poll design. Fix: carry `sid` and the issuer kind into every stream re-check, at most every 10 seconds for platform tokens, or restate the bound for streams; the test measures it. Confirmed in code.

17. **Major. Technical Plan 4 (Signing keys), Architecture decision 0140 decision 7.** The verifier holds only `PUBLISHED` and `ACTIVE` keys while the record keeps a retired key verifiable; retiring at the token lifetime after activation ignores the refresh lag and leeway; a replica whose refresh failed refuses new tokens with no refresh on an unknown `kid`. Fix: keep `RETIRED` keys until the next activation plus lifetime, refresh interval and leeway; refresh on an unknown `kid` (rate-limited); stop signing when the set is older than two intervals; drive the test by a controlled clock. Confirmed in the documents.

18. **Major. Requirement 013-001, the connection revisions.** `TESTED` and `ACTIVE` are not bound to the tested revision: a change made during a test sign-in is activated untested. Fix: record the revision on the test attempt; `TESTED` by compare-and-set on it; `ACTIVE` only if unchanged since; a barrier test. Plausible.

19. **Major. Technical Plan 4 (Begin), Requirement 013-021.** The silent path's new session would carry a fresh authentication time, so a reload passes the "signed in within the last 10 minutes" guard and a raised context, and each reload adds a session against the cap. Fix: a silent code reuses the existing session, or copies its time and context and ends the old one; `a_silent_sign_in_is_not_recent`. Plausible.

20. **Major. Requirements 013-011, 013-012, CUJ 1.** Linking to an existing subject has no flow: no proof of the current subject in the attempt, no confirmation step or binding, no transaction; a test sign-in both "writes nothing" and writes a link and `TESTED`. Fix: the link flow starts from an authenticated Studio session recorded on the attempt; a confirmation `POST` with the renewal protections writes the link and audit under the membership lock; the test sign-in's `TESTED` write is part of it; a positive test. Confirmed in the documents.

21. **Major. Requirements 013-016, 013-020.** Suspension changes only `status`; reveal grants (whose trigger fires on `UPDATE OF role`), 029 assignments, folder entries and secret lists survive and come back on reactivation, the defect migration `20261220000000` fixed for role changes. Fix: decide and state it (suspension revokes them in its transaction, or reactivation restores them with an audit), with a test. Trigger scope confirmed in code.

22. **Major. Requirement 013-013, `member_profiles`, Decision 013-017.** The owning connection's lifecycle is unspecified: on its deletion what the owner and the default become; while disabled its SCIM is refused, so offboarding stops for its members silently; an ownership change does not say it recomputes. Fix: the foreign key behaviour, the fallback without an owner, an alert listing the members of a disabled owner, recomputation on ownership change. Plausible.

23. **Major. User story 013-05, Requirement 013-021.** Nothing stops the tenant losing its last administrator through SCIM, a mapping change or the member routes. Fix: refuse with `LOCKOUT_GUARD` any change that leaves zero active `admin` members, counted under the tenant identity row lock; a test. Plausible.

24. **Nit. Requirement 013-018, Technical Plan 10.** The Studio renews before expiry whether the person is active or not, so the idle expiry never fires for an open tab. Fix: renew only after user activity, or define idle as no client holding the session.

25. **Nit. `signin_attempts`, `signin_codes`, the purge.** A code issued near the attempt's expiry outlives it, and the purge can delete the attempt first. Fix: code expiry `min(60 s, attempt expiry)` or copy the identity onto the code; purge attempts after their codes.

26. **Nit. Requirements 013-022, 013-031.** Unique violations on unlisted constraints map to `Internal` (500): two tenants verifying one domain, two connections with one slug. Fix: name each new constraint in `classify`; barrier tests.

27. **Nit. Break-glass uses.** Two first requests with one token race on the unique row and the loser reads as a failed audit. Fix: `INSERT ... ON CONFLICT DO NOTHING`, the audit and alert written by the inserting transaction only.

28. **Nit. Technical Plan 2 against Requirement 013-016.** The architecture rule fails on today's tree: the two plain reads are outside `crates/infra-postgres/src/identity.rs`. Fix: move them, or list them as the only exceptions.

29. **Nit. Technical Plans 3 and 4.** Today's deployment-issuer path is two reads (`find_tenant_by_slug`, `find_membership`), not one. Fix: say the new statement merges two into one.

30. **Nit. Technical Plan 11.** `MEMBER_SUSPENDED` and `SESSION_REVOKED` cannot be told apart on the request path if the read returns active rows only. Fix: return the status and map it, or keep the reasons for renewal and refresh.

31. **Nit. Tasks 013-10 and 013-8.** `a_revoked_session_is_refused_on_its_next_request` does not say where the barrier holds the request (after the read, the in-flight request succeeds and the next is refused); the key test needs a controlled refresh. Fix: state both oracles.

32. **Nit. Requirement 013-032, Rollout, `instances.rs`.** During activation replicas learn the requirement at their next beat (about 12 seconds) and answer differently; the removal's check does not take the lock the federated-only enable path takes. Fix: check the recorded requirement in the writer's transaction through a definer function that takes the epoch lock shared; state the window.

33. **Nit. Technical Plan 3.** The case rule of the `federated:` checks is unstated (`system:` is case-insensitive). Fix: all three checks case-insensitive; test `FEDERATED:x`.
