**Verdict of the reviewer.** Neither builder could start the whole plan without questions: the server part of Task 050-9 had no decided data source, and every Studio task waits on pull request #267 without the plan saying so.

1. **Blocker. Task 050-9, Technical Plan 5.** "The projection in `crates/infra-postgres`" does not exist: the graph is built in `dto_exec.rs` from `GraphSnapshot` (steps, sagas, chain), the progress tables have no failed outcome (`collection_iterations` and `loop_iterations` lifecycles `ADMITTED`, `CHECKPOINTED`, `DRAINED`; `iteration_scopes` holds no failed index or code), the failed iteration exists only in the drain event's reason, and `graph_changes` re-reads the snapshot each poll. The builder must choose a source; the contract is blocked on it; the `instancePath` query encoding is undefined. Fix: name the tables, columns, migration, function and crate, the derivation of `FAILED`, the query syntax and cursor under a filter, and the test's target.
2. **Major. Task 050-4, `decide`.** Where the `RunEnded` check goes relative to replay and `AlreadyDecided` is not said; placed first it breaks replay after a run ends and the golden `approval-settlement.json`. Fix: only after authorization, with no winning receipt and a `Pending` status; `may_decide` mirrors it; a replay test.
3. **Major. Task 050-4, Non-functional requirement 050-003.** A run end cancels its approvals, so a pending approval of an ended run cannot be reached through public calls and the SDK suite seeds no private store; the approval scenarios run in five SDKs, and scenarios are JSON files. Fix: prove `RUN_ENDED` in the Rust integration target by seeding; SDK unit tests of the `409` classification; five SDKs; name the file.
4. **Major. Task 050-2, Technical Plan 9.** `x-implemented` before the routes exist fails the cross-tenant battery (an unrouted path answers `ROUTE_NOT_FOUND`); the repository uses `x-planned` first. Two pinned digests change (`contract_payload_classification`, `contract_iceberg_writes`). `contract_platform_foundation` is not the OpenAPI lint; the lint is the redocly command of CI. Fix all three.
5. **Major. Task 050-11, Decision 050-006.** `npm run check:api` regenerates types only; `openapi-typescript` drops `x-` extensions and the Studio has no YAML parser, so `x-known-values` never reaches it; the domain crate has no parser for the comparison test. Fix: one source the Studio can import, and the comparison in a `tests/contract` target.
6. **Major. Task 050-9, `useIntentKey`.** `options.key` sets the `Idempotency-Key` header, while the decision and the Update take `decisionKey` and `updateKey` in the body; `ApiClient` has no retry, which Gap 050-001 relied on. Fix: the hook fills the body field; say whether a resend is automatic or the person's.
7. **Major. Task 050-6, the body pointer.** `IrError` variants carry only a node id, so most body problems lose the body name and index; `resolveNodeId` reads `nodeId` before the path, so a colliding root id still wins. Fix: list the variants that gain a body scope, keep or drop `nodeId`, read the body pointer first, a server-side red test with its target.
8. **Major. Tasks 050-6 to 050-8.** `HandleSpec` cannot express nested `cases[i].target`, and `EdgeKind` lacks the switch and approval routes; no edit operation reads bodies and no task owns the body model; `a_duplicate_id_entry_in_a_body_keeps_its_index` passes today; no Studio module reads `GET /version`. Fix: a nested handle form and edge kinds, a body-document adapter task before Task 050-8, move that test after it, name the capability hook.
9. **Major. Task 050-7.** Component tests run on fake route maps; a real server exists only in the journeys. Fix: a mocked `validate` per kind, and publication as a journey case.
10. **Major. Task 050-3.** `platform_version` takes no state and `/version` is mounted in two routers; the harness builds its own router, so a harness test would not exercise the start-up computation; the switch is in `DefinitionService` and `config.rs`, not `infra-ir/src/capabilities.rs`; Architecture decision 0143's variant check has no task. Fix: one pure mapping function used by both, the `AppState` field, the target, the variant test.
11. **Major. Plan introduction.** Tasks 050-1, 050-2, 050-13, 050-14, the SDK work and every `tests/` target have no owner; pull request #267, feature 041's Logs tab, 022's registry move and 029's `x-access` are predecessors named only in Technical Plan 1. Fix: assign them; make the external gates explicit.
12. **Major. Tasks 050-3 to 050-12.** Most tasks have no verification command; `integration_studio_catch_up` has no `[[test]]` entry; the test paths in the decision records are not compiled by any target. Fix: a path and a command per task; create the target in Task 050-4.
13. **Major. Task 050-13.** The harness does not enable collection operators nor seed a tenant collection policy (no route records one); the CI job caps at 60 minutes. Fix: list the harness changes and a time budget per journey.
14. **Major. Task 050-14.** No target, tool or seeding is named for the three measurements. Fix: name them and the report path.
15. **Major. Tasks 050-4, 050-5, Technical Plan 6.** "As the decision does" builds the principal inside the adapter's transaction; `list_for_run` returns no policy snapshots yet must give `youMayDecide`. Fix: the port traits, signatures and row types; where the role is read; the change to `list_for_run`; the publication port and how `approvalsRequiredNow` is read.
16. **Nit. Technical Plan 4.** `WorkflowSettings.tsx` already edits `inputSchema`. Fix: say it keeps it.
17. **Nit. Task 050-12.** `SAMPLE_SOURCE` has no Go or Java sample. Fix: name the samples.
