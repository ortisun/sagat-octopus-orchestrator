1. **Blocker. Overview, The Problem, Technical Plan 3 (`workflow.structured-primitives`), Requirements 050-003 and 050-007, Success criterion 050-001, CUJ 1, CUJ 4, Architecture decision 0143.** No runtime switch called "structured primitives" exists. Production publication (`published_definition`, `crates/infra-ir/src/lib.rs`) always accepts `forEach`, `while` and `repeatUntil`, but only in fixed shapes: a collection workflow is a collection chain ending at `end`; `while`, `repeatUntil`, `approval`, `continueAsNew` and `return` beside a collection are refused; a loop workflow is a loop chain ending at `end` with recovery activities only; an activity after a loop's success edge is refused; collection bodies hold only activity, condition, switch, timer, wait-event and return, one to eight steps; loop bodies are activity chains only; an approval inside a body is pending scoped compensation; a document with declared `state` refuses `bodies`; triggered loops and collections are refused (`crates/infra-ir/src/convert.rs`). A yes-or-no capability cannot describe what publishes; Success criterion 050-001, CUJ 1 and CUJ 4 describe unpublishable workflows, and the body palette would offer refused kinds. Fix: remove `workflow.structured-primitives` (loops need no capability); state the publishable subset as placement rules per kind and scope in the design and the registry, held to `convert.rs` by a parity test (as `crates/domain/tests/outcome_unknown_parity.rs`), with `validate` the authority; offer in bodies only what the codec accepts; rewrite the criterion and the journeys as workflows that publish today, or declare an engine dependency with an `Owner-gate:` line.

2. **Major. Technical Plan 3, last paragraph; Architecture decision 0143 decision 2; Gap 050-001.** The list is "cached for the life of the process" yet "computed from the instance registry's recorded requirements", which an operator activates at runtime and a process learns within one heartbeat (Architecture decision 0082 decision 4); feature 022 activates two requirements separately and 029's `access.restricted.*` names follow `access-narrowing-v1`. Two vocabularies exist (the registry's typed `Capability`, `*-v1` names, in `apps/control-plane/src/registry.rs`, and the dotted names) with no mapping; the owner of the vocabulary, the meaning of a missing field (an older replica) and whether names are deployment-wide or per tenant are unstated. Fix: a typed `PlatformCapability` enum in `crates/application`; names from static configuration computed once and names from the registry re-read from the requirement set the heartbeat carries; one tested mapping table; names deployment-wide, never per tenant; a missing field means a server before 0.3.0, and the Studio says what it offers then; record it in Architecture decision 0143.

3. **Major. Technical Plan 3 table; 029 `contracts/README.md`; 028 `research.md` Decision 1409 and Decision 028-008; FR-027-037.** The "closed list" is neither closed nor in step: 029 advertises `access.groups` and `access.external-groups`, absent from 050's table; 028's Decision 1409 still advertises `history-replay` and an unprefixed `virtual-clock`; `<kind>` and `<id>` are templates, not members; `workflow.flow-control` merges 022's two capabilities; a closed OpenAPI `enum` on a response makes every new name a breaking change for strict readers (the SDK test environments of 028), against "readers tolerate what they do not know" (`docs/engineering/architecture-principles.md`). Fix: enumerate every concrete name now and reconcile 027, 028 and 029; two names for 022; declare the field `type: string` with a pattern and list the known names in its description or `x-known-values`; a contract test that a reader ignores an unknown name.

4. **Major. Technical Plan 6 (server), Requirement 050-010, Architecture decision 0144 decision 2, Verification Plan.** The SQL predicate is a second rule written by hand; SQL text in `crates/domain/src/execution/approval.rs` brings adapter column names into the domain; a property test in `crates/domain` cannot run SQL; `ApprovalPolicy::admits(subject, role, initiator)` puts the initiator on the policy, whereas it belongs to `ApprovalRequest`, and Architecture decision 0144 names `ApprovalRequest::decide` as the oracle; the decision path also refuses an approval pending on an ended run and re-reads the role from `memberships` (`crates/infra-postgres/src/approval_progress.rs`), which the predicate does not model. Fix: extract `ApprovalRequest::may_decide(&Principal) -> bool` from `authorize_decision` and call it from `decide`; the adapter returns the bounded page of pending rows with their snapshots and the use case filters with `may_decide` on a principal from the current membership, so no SQL predicate exists; the property test becomes pure domain; an approval pending on an ended run is not decidable.

5. **Major. Requirement 050-011, Technical Plan 6, Task 050-5.** The publication rule leaves out "a person decides once" (Architecture decision 0018 decision 4; `PublicationRequest::decide`, `crates/domain/src/versioning.rs`), so an approver who already approved a two-approval request would see `youMayDecide: true` and get `ALREADY_DECIDED`; the rule lives in the domain, not in `crates/application/src/publishing.rs`; `status=OPEN` does not exist (states `PENDING`, `APPROVED`, `REJECTED`, `WITHDRAWN`, `SUPERSEDED`, `PUBLISHED`; `is_open` covers `APPROVED`, which waits to be published). Fix: `PublicationRequest::may_decide(&Subject)` in the domain with all three clauses, used by `decide`; `publication:approve` checked in the use case; filter on `PENDING`; a test that a person who decided may not decide again.

6. **Major. Requirement 050-010, Technical Plan 6.** The only new index is partial on `PENDING`, but the route accepts other statuses ordered by deadline, which no index serves, so it sorts every settled row of the namespace; the scan bound covers only the pending index; the migration's lock cost and `down` are unstated. Fix: limit the namespace route to `PENDING` (history stays on the per-run list and the audit page), or add a second partial index by `settled_at` with the same bound; write the `down` and the lock cost.
