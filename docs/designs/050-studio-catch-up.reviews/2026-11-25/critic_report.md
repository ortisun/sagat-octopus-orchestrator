The reviewer found every section the feature-spec standard asks for present, with alternatives and reasons recorded; the findings are claims that do not hold against the code and contracts, and risks at scale the Risks table missed.

1. **Major. CUJ 4, Requirement 050-008, Technical Plan 5 "Iterations".** The journey and the status list assume a collection keeps running after iterations fail; the engine stops it at its first permanent failure (`CollectionDrainReason::Failed { iteration, code }` starts a drain; in-flight iterations end as `CollectionIterationDrained`; `forEach` has no setting to tolerate failures). "1,988 succeeded and 12 failed" cannot happen; the status set has no drained or not-admitted value; the cited drain reasons are per collection, not per iteration. Fix: statuses from the per-iteration events, add `DRAINED` and a not-admitted count, rewrite CUJ 4 as one failure that stops the collection, correct the citation.
2. **Major. Technical Plan 5, Requirement 050-008.** The new fields change without an event naming the node that carries them, so `graph/changes` (which re-sends only touched nodes, `graph_changes_body`) leaves them stale: `RETRYING` and `RUNNING` counts drift on step retries, and `iterationStatus` on every instance changes when an iteration returns. Fix: one rule (touch the owner and all instances of an affected iteration, or keep statuses on the owner and make body events touch it) and a red test comparing `graph/changes` with a fresh graph across a retry and a return.
3. **Major. Requirement 050-008, Non-functional requirement 050-002, Risks row "10,000 iterations".** Only rendering is mitigated; `RuntimeGraph` has no `maxItems`, a 10,000-item collection over an eight-step body is more than 80,000 nodes sent whole on every `reset`, and the requirement measures neither download nor parse. Fix: counts and a paged iteration list, instances only for the opened iteration; or at least measure payload size and parse time and add the risk.
4. **Major. Technical Plan 6 "Studio", Requirement 050-012, Non-functional requirement 050-002, Risks.** The refresh cost is not estimated: up to ten requests per tab every 30 seconds against a tenant budget of 100 per second with a burst of 200 (`limits.rs`); about 300 open tabs exhaust it and starve workers. Fix: state the rate for N inboxes and measure it, refresh only the visible tab, one page on a timed refresh, back off when unchanged, consider a "changed since" answer, add a risk row.
5. **Major. Goals, User story 050-02, Requirement 050-012, CUJ 6, Non-Goals.** "One place for what waits for a person" but the inbox is per namespace; no Non-Goal excludes a tenant-wide inbox and no decision weighs it. Fix: a Non-Goal and reworded goal and story, or a count per namespace; record the choice as a Decision.
6. **Major. Requirement 050-002, Technical Plan 3 table.** `workflow.step-destinations` has no switch and no reader: the codec always refuses destinations (`DESTINATIONS_NOT_ENABLED`), so its acceptance test cannot be run and a name of undefined meaning enters `x-known-values`; it contradicts Stage 5 finding 2. Fix: ship only `workflow.collection-operators`; feature 035 adds its name with its switch and test.
7. **Major. Architecture decision 0144 decision 1.** The record still requires workflow and run filters on the namespace route, which the design removed when it settled Stage 5 finding 4; the binding record and the design disagree. Fix: amend decision 1 (no filters; `youMayDecide` on the per-run and per-workflow lists), add the per-run flag to decision 2, in the same delivery.
8. **Major. Requirement 050-011, Technical Plan 6, Non-functional requirement 050-001.** The fields of a publication inbox item are not stated; reusing `PublicationRequest` would carry `decisions`, `requestedBy` and `editedBy`, which decision 3 of Architecture decision 0144 may be read to forbid, and the contract test covers only the approvals inbox. Fix: list the fields (reuse with a stated exemption, or a reduced item), extend or exempt the contract test, reword decision 6.
9. **Nit. Non-functional requirement 050-003, Overview.** Two changes are not purely additive: `503` to `409 RUN_ENDED` changes retry classification in six SDKs, and `ApprovalListItem` is a closed schema whose SDK descriptions say it carries no eligibility. Fix: name the error change as deliberate with a conformance check; say the schema is opened; update the SDK descriptions.
10. **Nit. Gap 050-001, Technical Plan 3.** A new Studio reaching an older replica meets three unhandled answers: `404 ROUTE_NOT_FOUND` on the new routes, no `youMayDecide`, the old `503`. Fix: one sentence each ("not available on this server"; absent flag means unknown and the decision is offered; the `503` retried within the existing bound).
11. **Nit. Requirement 050-005, Technical Plan 4.** "Linked from the legacy node's predecessor" does not say which handle, whether the edge moves, or what happens with several predecessors or an entry node. Fix: the new node takes every incoming edge; with no predecessor it becomes the entry; test both cases.
12. **Nit. Architecture decision 0143 option 3 against Decision 050-009.** The record rejects "offer every kind and rely on `validate`" for the very behaviour Decision 050-009 chooses for placement and shape. Fix: limit the rejection to kinds a deployment switches off; say shape refusals are knowingly left to live validation.
13. **Nit. Gaps.** Gap 050-005 comes before Gap 050-004. Fix: order them.
14. **Nit. Tasks and Verification Plan.** Task 050-12's red tests still read the superseded server-driven Go and Java version, and the Verification Plan still lists "the registry-derived capabilities". Fix: align with Requirement 050-019 and Technical Plan 3.
