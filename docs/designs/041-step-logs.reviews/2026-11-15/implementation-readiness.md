## Blocker

1. The contracts T041-3 freezes are not settled (ir-1-1, cd-1-1). T041-3 (844-848), T041-11, T041-12, T041-23, T041-30, sections 1 and 5 (410-428, 579-619). Missing: proto field numbers, enum values (level, kind, `DROPPED` reason, verdict), the field and unit of the `RETRY_LATER` delay, the exact `StepLogPolicy` fields; OpenAPI item schemas of `listRunLogs` and `listRunLogStreams`, the closed stream states, the "how far behind" field (591-592), the SSE payloads and `Last-Event-ID` format, the format of `from`/`to`/`stream`, the status and body of `deleteRunLogs`; error codes: `FEATURE_DISABLED` (line 585) is not in the closed `Error.code` enum (`specs/001-platform-foundation/contracts/openapi.yaml:4881`; checked by `tests/support/contract.rs:186`; switches are a code plus `details.reason`, as `LAKE_DISABLED`), and no code is given for a missing permission, a missing grant (`PII_REVEAL_NOT_GRANTED` exists), a foreign cursor (existing cursors answer `BAD_REQUEST`, `crates/api-http/src/routes/primitives.rs:193-205`), `q` over 128 characters or the tail caps. The polling fallback of `followLogs` has no end condition: `followRun` stops on a terminal run status (`frontend/apps/studio/src/api/follow.ts:133-137`), and the list route carries neither status nor horizon. *Recommendation:* a contract appendix (or `specs/041-step-logs/contracts/`) with the proto messages, the OpenAPI schema fragments, an error table (refusal, code, reason, status) and the poller's end rule.
2. The SDK logger APIs the scenarios need do not exist, and the level mapping is open (cd-1-2, ir-1-9). FR-041-003, FR-041-007 (99-103, 126-128), section 6 table (627-634), T041-14 to T041-20. Java's `ActivityLogger` has only `log(System.Logger.Level, String)` and four level methods, with no fields and no `Throwable` (`sdks/java/sdk/src/main/java/dev/sagatoctopusorchestrator/sdk/worker/ActivityLogger.java:7-24`), so FR-041-007's "Java fields" is false; TypeScript has no `trace` (`sdks/typescript/src/worker/activity.ts:87-92`), nor do Go `slog` or Python; `step-logs-capture` asserts five levels and typed fields, and `step-logs-redaction` a secret inside an exception, while FR-041-015 keeps each logger type. Open: per-language level table (Python `CRITICAL`, C# `Critical`/`None`, Java levels, Go intermediate levels), whether the capture floor bypasses the host's `isEnabledFor`/`Enabled`/`IsEnabled`, where exception text goes, argument formatting and field flattening (`slog` groups, C# scopes), whether Go captures the identifiers it attaches with `With(...)` (`sdks/go/worker/task.go:176`) when Python strips its own, the Rust `ActivityContext::log()` signature, the per-process option names, the spacing of the two retries. *Recommendation:* a per-SDK API table (new methods and overloads, level mapping, excluded attributes, option names, the Rust signature) as a deliverable that gates T041-15 to T041-20; correct FR-041-007.

T041-13 (923-926), section 7 (674-683), D041-021. `script_executions` has `instance_id`, `instance_path_nodes`, `instance_path_indices` (`crates/infra-postgres/migrations/20261027000000_scoped_instance_identity.up.sql:82-91`), but `NewExecution` has no instance field (`crates/application/src/scripts.rs:283-301`) and the insert never writes those columns (`crates/infra-postgres/src/scripts.rs:1856-1863`), so "when the report carries it" never happens; the run-less arm of `record_execution` (`:1828-1838`) and the gating by the two switches are not addressed. *Recommendation:* state that the instance path is null until the runner reports one (G041-007), that no marker is written without a run, and how the switches gate it, or drop the write (stage 5 #2).

Only `step_log_retention_days` is named; the two attempt and two run ceilings and the switch have no name, kind, unit, maximum, default or validation (`crates/domain/src/quota.rs:142-408, 538-560`); `Policy` refuses 0; the `Retention` kind and the OpenAPI `Quota` text ("Lowering a limit does not erase retained content", `openapi.yaml:6537-6538`) contradict FR-041-020; the CHECK constraints `quota_limits_resource_valid`, `quota_ceilings_resource_valid` and the per-resource range (`20270102000000_batch_operations.up.sql:11-27`), the `Quota.resource` enum (`openapi.yaml:6542`) and an ingest step that reads the namespace policy are not in any task; the purge's per-namespace retention needs a SQL resolution of defaults that live in Rust. "At the scope the catalogue allows" hides the stop condition of the open question, which is answerable (`QuotaScope::Namespace`, `quota.rs:112-117`). *Recommendation:* a resource table (name, scope, kind, unit, range, default, ceiling, meaning of 0); the constraint migration and OpenAPI changes in T041-4; a numbered ingest step; the purge's retention lookup; close the open question.
