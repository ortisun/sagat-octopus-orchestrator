# Glossary

- **Workflow Definition:** versionable logical design of the process.
- **Workflow Version:** published, immutable artifact, with IR and hash.
- **Run:** workflow instance with its own inputs, status and history.
- **Step:** logical work node, with stable identity.
- **Attempt:** physical attempt of a step with lease/fencing.
- **Activity:** code executed by a customer worker (SDK / BYO worker).
- **Inline Script:** code stored/published in the registry, automatically compiled or prepared, and executed in the platform sandbox.
- **Script (draft):** the code an author edits in a namespace — source, lockfile, input and output JSON Schemas, limits, retention — with a revision that makes concurrent edits conflict instead of overwrite.
- **Script version:** the draft frozen when it is published; numbered, immutable, `BUILDING` → `READY` (an artifact) or `FAILED` (a reason).
- **Artifact (script):** what a build made: a canonical bundle of the code, the limits and the schemas it was built under, identified by its digest and signed by the control plane. A workflow pins the digest.
- **Build key:** the hash of the source, lockfile, toolchain, limits and schemas of a build; an identical key is never built twice.
- **Sandbox:** a container made for one build or one run — no network, read-only root, no capabilities, hard limits — whose only way out is its supervisor.
- **Runner:** the process that holds the container engine and builds and runs scripts for one tenant; it has no database and is trusted only with what its token reaches.
- **Test run:** a draft built and run with an input without publishing it; no secrets of the namespace, its own quota.
- **Execution record:** what a published script did in one attempt of a step — the redacted log, what it was refused, the numbers — kept for the script's retention.
- **Journal:** ordered append-only record of decisions/transitions.
- **Outbox:** transactional queue for commands/events external to the DB.
- **Inbox:** deduplication/durability of received external messages.
- **Saga:** coordination of actions with semantically defined compensations.
- **Reconciliation:** querying external state to resolve an ambiguous outcome.
- **Compensation:** the activity that asks a provider to undo a completed step (`compensateWith`); a step of its own, `<id>~c`, planned in reverse order. Not a rollback.
- **Lookup:** the reconciliation step `<id>~r`; its answer is `applied`, `not_applied` or `unknown`.
- **Derived node:** a compensation or lookup the engine adds to the definition for an activity that declares one; nothing routes to it.
- **Manual review:** the state of a run (`MANUAL_REVIEW`) while a step waits for a person to retry it, skip a compensation or declare what happened.
- **Partial:** how a saga ends when something could not be undone (`irreversible`, or a compensation an operator skipped).
- **Circuit breaker (compensations):** the rule that stops handing out the compensations of an activity that keeps failing, then lets one probe through.
- **Event:** a fact that came from outside (a signed webhook, the API, a broker message, a calendar tick), with a source, a type, an id the provider chose and optionally a subject and a correlation key. Identified by `(tenant, namespace, source, event id)`.
- **Source:** where an event came from: the slug of an event endpoint or a connector, `api` or `cron`.
- **Event endpoint:** the random URL (`/v1/webhooks/{id}`) a provider posts signed events to, with its secret, limits and dedupe window.
- **Inbox event:** an admitted event in `inbox_events`: durable once the provider was told `202`, deduplicated for its window, dispatched asynchronously.
- **Trigger:** what starts a run from an event or a schedule (`event`, `webhook`, `message`, `cron`, `manual`), registered when a version is published; its id is stable across versions.
- **Correlation key:** the value a waiting step and the events it wants have in common (an order id).
- **Look-back:** how far before a wait began an event may have arrived and still wake it (`lookbackMs`).
- **Dispatcher:** the loop that matches admitted events to triggers and waiting steps and records, in the same transaction as each effect, that it did.
- **Webhook subscription:** a receiver of outgoing events (`run.finished`) with its URL, signing secret, rate and health.
- **Delivery:** one event owed to one subscription: attempts, outcome, and a stable delivery id; `DEAD` when it can never work, then redrivable.
- **Connector:** a reader of a Kafka topic, an SQS queue or a NATS JetStream stream that turns messages into events, acknowledging only after the event is in the inbox.
- **Dead letter (connector):** a message that could not become an event, kept (bounded) with the reason for a person to redrive or discard.
- **Signal:** message addressed to a specific Run.
- **Wait subscription:** durable event→Run/step binding, with deadline.
- **Lease/fencing:** temporary versioned authorization that prevents a stale attempt from committing.
- **IR:** canonical intermediate representation of the workflow interpreted by the engine.
- **Control plane:** APIs, definition, management, authoring.
- **Execution plane:** scheduler, journal, workers, Saga engine.
- **Observability plane:** projections, logs, traces, metrics and UI.

- **Payload classification:** the author-declared `public`, `internal`, `pii` or `secret` level on a supported payload schema. Descendants inherit the strictest level; an undeclared property is at least PII. This is a disclosure policy, not secret storage.
- **Disclosure carrier:** the pinned workflow input/result schema or eligible node output schema which governs one retained payload. Native managed database outputs are outside this closed carrier set.
- **Payload reveal grant:** an audited, namespace-scoped grant allowing a current internal-read role to request PII explicitly. No built-in role, including admin, receives it automatically.
- **Classified disclosure:** the explicit, bounded, non-cacheable read of permitted values. A successful PII reveal commits its audit before values are returned; structural inspection remains a separate operation.
