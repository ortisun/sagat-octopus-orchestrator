# crates/domain/src/execution

## Overview

Pure execution-domain aggregates, journal vocabulary, reducers, planners and exact-instance identities. Time, jitter and evaluated data arrive as arguments; domain events require adapter persistence. Capacity-transfer gates remain dormant and do not enable nested execution.

## Invariants

- Commands validate/apply their primary event and deterministically settle; ordered returned events and resulting state are an adapter persistence contract, while `Evaluation` represents outside data still needed. [command.rs:apply_then_settle] [command.rs:settle] [plan.rs:Evaluation]
- Lease authority requires the appropriate leased/running status and matching attempt/generation for root, full scoped and bounded-path commands. Unknown-effect failures may request reconciliation or wait for review instead of retrying blindly. [command.rs:require_lease] [command.rs:require_instance_lease] [command.rs:require_path_lease] [command.rs:end_attempt] [command.rs:fail_scoped_attempt]
- Approval policies contain 1–32 unique eligible subjects/roles; keys are 1–128 printable non-space ASCII and reason codes are 1–64 machine-code characters. Tenant/permission/policy/initiator checks precede replay, and resolved status constrains later decision/expiry/cancel transitions. [approval.rs:ApprovalPolicy::with_initiator_exclusion] [approval.rs:DecisionKey::parse] [approval.rs:ApprovalReasonCode::parse] [approval.rs:ApprovalRequest::authorize_decision] [approval.rs:ApprovalRequest::decide]
- Capacity headers use monotonic revision/possession epoch and consistent restored counters/holder facts. Membership identity is non-reusable. Dormant transfer gates require adapter-held guards; possession grants no execution permission and no creator, scheduler caller or nesting acceptance is established here. [capacity.rs:CapacityGroup::restore] [capacity.rs:CapacityGroup::join] [capacity_transfer.rs:acquire_gate] [capacity_transfer.rs:vacate_gate]
- Continuation transitions pin inherited scope/version/deadline fields, enforce head/revision CAS, quiescence, unique bounded segments and replay identity/content, and latch cancellation/finality. Deadline/tree-budget error variants alone are not evidence that a transition enforces those runtime limits. [continuation.rs:ExecutionChain::continue_as_new] [continuation.rs:ExecutionChain::validate_inherited_fields] [continuation.rs:ExecutionChain::replay_or_reject_handoff] [continuation.rs:ChainError]
- Declared updates deduplicate by scope/key, reject conflicting reuse, mutate only RUNNING/WAITING state, preserve schema and advance applied state revision once; rejected receipts do not advance it. [operations.rs:DeclaredOperationsState::resolve_update_inner] [operations.rs:UpdateReceipt::validate_stored]
- Logical paths have at most eight scopes with indices 0..=9999; attempt/generation is excluded from instance identity. Bounded paths require complete ordered ancestry, and derived work requires compensation/reconciliation authority. [instance.rs:MAX_SCOPE_DEPTH] [instance.rs:MAX_ITERATION_INDEX] [instance.rs:ExecutionInstanceId] [path_state.rs:PathExecutionState::restore] [path_state.rs:PathExecutionState::authorizes_derived_work]
- Scoped controls/timers/waits reject wrong kind/path/state or stopped ancestry; explicit due times and event type/correlation/lookback constrain timed/event transitions. [scoped_controls.rs:prepared_event] [scoped_timers.rs:prepared] [scoped_event_waits.rs:prepared_start] [scoped_event_waits.rs:prepared_satisfaction] [scoped_event_waits.rs:prepared_timeout]
- Saga planning includes successful/unknown-outcome effects, reverses dependencies and retains irreversible/high-risk unresolved effects. Structured planning/drain paths retain explicit unsupported cases; source vocabulary does not enable general nesting or establish workload ceilings. [sagas.rs:plan_entries] [sagas.rs:compensate] [scoped_sagas.rs:next_compensation] [plan.rs:start_pending] [plan.rs:drain]
- New leases increment attempt and generation by one; accepted leased events require exact current values. Trusted projection constructors require consistent storage-derived facts; `RunWorkSummary` additionally requires live work to be active and review to be waiting. [state.rs:StepState::apply_instance_lifecycle] [state.rs:RunState::fenced_step] [state.rs:StepState::restore] [state.rs:RunWorkSummary::restore]
- Collection restoration/events check max-items bounds, item count, concurrency 1..=256, contiguous indexes, exact child paths and active count; successful collections require all items checkpointed. [state.rs:RunState::restore_collection_progress] [state.rs:RunState::apply_collection_event]
- Loop restoration/events check iteration bounds, timeout 1..=31_622_400_000 ms, While versus RepeatUntil initial-condition rules, and checkpoint timing/index/continuation semantics. [state.rs:RunState::restore_loop] [state.rs:RunState::apply_loop_event]
- Finished runs reject more events. Finish checks terminal steps and ordinary-success routing, and stop-derived finality incorporates applicable saga outcomes. Continuation requires quiescence, no stop/pause, bounded membership and a distinct successor. [state.rs:RunState::apply] [state.rs:RunState::check_finish] [state.rs:RunState::final_status_for]
- Reconciliation verdict/result pairs and operator-held transitions are closed; only compensation steps may be skipped. [state_effects.rs:apply_effect_event]

## Side Effects

- Root/scoped commands mutate supplied run/path state and return journal events; planners select events/evaluations without persisting or publishing. [command.rs:apply_then_settle] [command.rs:settle_addressed] [command.rs:settle_path] [plan.rs:plan] [plan.rs:plan_addressed] [plan.rs:plan_path]
- Approval, capacity, chain and child-link methods mutate in-memory aggregates. Durable membership, authorization lookups, audit, timers/subscriptions, journal/outbox writes and scheduling belong to adapters. [approval.rs:ApprovalRequest::decide] [capacity.rs:CapacityGroup::acquire] [continuation.rs:ExecutionChain::continue_as_new] [continuation.rs:ChildChainLink::observe]
- Declared updates invoke the caller evaluator after admission and locally update state/receipts; persistence remains external. Qualified event/control/timer helpers locally apply events and settle routing. [operations.rs:DeclaredOperationsState::resolve_update_inner] [scoped_event_waits.rs:satisfy_event_wait_instance] [scoped_controls.rs:resolve_control_instance] [scoped_timers.rs:fire_timer_instance]
- Reducers mutate in-memory run/step projections and advance the applied journal sequence for legal events. Collection/loop drains can mark scoped work failed/cancelled and clear wait/retry/cancellation fields; replay performs no direct I/O. [state.rs:RunState::apply] [state.rs:RunState::apply_addressed] [state.rs:RunState::apply_collection_event] [state.rs:RunState::apply_loop_event] [state.rs:RunState::replay]
