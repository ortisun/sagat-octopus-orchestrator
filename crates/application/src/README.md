# crates/application/src

## Overview

Application use cases, typed commands/results and storage/provider ports. Services enforce local authorization and validation and coordinate effects; durable atomicity, current-authority rechecks, receipt/journal/outbox semantics and reconciliation are adapter responsibilities where specified by ports.

## Invariants

- Authorization/canonical scope resolution precede durable namespace rate admission; foreign resources are opaque NotFound with bounded/best-effort denial auditing except explicit durable denial ports. Approval and binding ports require current authority plus atomic grant/session/lease/audit or approval/journal/route/timer/outbox changes; services do not implement storage locks themselves. [api_admission.rs:ApiAdmissionService::admit] [authz.rs:require_namespace] [approval_progress.rs:ApprovalProgressStore] [approval_scheduler.rs:ApprovalScheduler::open] [bindings.rs:BindingStore::replace_binding]
- Blob capacity is reserved before provider I/O; streaming enforces size/digest and reads verify through EOF. Cleanup claims precede deletes and uncertain uploads retain evidence. Collection materialization requires matching committed same-run ownership, an 8 MiB source cap, item count, 256 KiB canonical item and 4 MiB aggregate retention. [blobs.rs:BlobService::write] [blobs.rs:BlobService::read] [blobs.rs:BlobCatalog::claim_delete] [collection_source.rs:CollectionItemSource::materialize] [collection_source.rs:canonical_items]
- Dormant ChildRoot receipts are historical outcomes, not current possession or execution permits; complete commands must be retained for same-key reconciliation. Chain signal/cancel lock the current head and validate CAS; continue_evaluated defaults unavailable until an adapter overrides it. [capacity_acquire.rs:CapacityAcquireResult] [capacity_discovery.rs:CapacityCandidate] [chain_progress.rs:ChainCommandService::signal] [chain_progress.rs:ChainCommandService::cancel] [chain_progress.rs:ChainProgressStore::continue_evaluated]
- Classification is bounded and value-redacting; unsupported/incomplete governance fails closed. Connector ingress/checkpoint atomicity belongs to ConnectorRuntime after bounded decode/admin validation. Egress reparses stored rules fail-closed and audits refusals without paths/query contents. [classification.rs:ClassifiedNode] [classification.rs:ProjectionFailure] [connectors.rs:decode] [connectors.rs:ConnectorRuntime::admit] [egress.rs:EgressService::policy_for]
- Database catalog/result ports recheck current authority/revision/receipts; blob result reads occur outside locks and are validated before transactional authority/digest audit recheck. Declared update hashes bind canonical arguments/CAS; chain identity excludes the moving head, while atomic state/result/receipt/journal/audit is a store contract. [database.rs:ConnectionStore::write_connection] [database_results.rs:DatabaseResultService::read_inner] [declared_operations.rs:declared_chain_update_request_hash] [declared_operations.rs:DeclaredOperationStore::apply_update]
- Publication validates IR/secrets/scripts/database access and requests one store transaction for version/active pointer/plans/triggers/pins/audit/dedupe. Discovery records do not authorize delivery; scoped waits require native transaction witnesses. Webhooks verify credentials before JSON and recheck exact trusted endpoint configuration during inbox admission. [definitions.rs:DefinitionService::publish_through] [definitions.rs:DefinitionStore::publish] [dispatch.rs:WaitingStep::root_node] [dispatch.rs:DeliveryRef::to_wait] [events.rs:EventService::receive] [events.rs:EventStore::admit_webhook]

[execution.rs:root_events_for_legacy_adapter] [execution.rs:root_outputs_for_legacy_adapter] [execution.rs:Engine::run_addressed]

[execution.rs:PathExecutionStore::begin_path] [execution.rs:PathExecutionTx] [execution.rs:RunTx]

[scripts.rs:ScriptService] [scripts.rs:RunnerService] [script_signing.rs:Signer] [script_signing.rs:Verifier]

Stores atomically update sealed values, ACL/pools and audit. Metadata-only service configuration disables local writes/reseal, non-managers receive ACL-filtered views, and reseal skips unopenable rows without changing them. [secrets.rs:SecretReader] [secrets.rs:SecretStore] [secrets.rs:SecretService::metadata_only] [secrets.rs:SecretService]

- Telemetry derivation uses applied journal sequence to avoid duplicate work; all_attempts reads at most 200 batches. [telemetry.rs:derive] [telemetry.rs:all_attempts]
- Worker protocol 1.6 capability negotiation is bounded by adapter/role support; scoped/database defaults refuse support. Database-runner identities require minor at least 1.6 and ordinary workers cannot use the reserved managed prefix. [worker.rs:PROTOCOL_MINOR] [worker.rs:WorkerStore] [worker.rs:WorkerService]
- Registration requires worker:execute, 1–256 activities, max-inflight 1–1,000, at most 16 labels of 1–64 characters and a 1–120-character name, with current bindings and atomic quota checks. [worker.rs:WorkerService::register]
- Polling caps a batch at 64 tasks/8 MiB and a task at 8 MiB, stops after three failed candidates, and checks current drain/session/protocol/pool/quota/breaker/pins in the transaction. Leases are returned only after commit. [worker.rs:WorkerService::poll_bounded]
- Worker reports require exact task/hash/attempt/generation, unexpired lease, current binding and stop fences. Only explicit cancellation acknowledgement relaxes cancellation. Replay is checked before mutation with exact run/identity and token-hash prefix; malformed acknowledgements fail closed. [worker.rs:WorkerService] [worker.rs:StepAck]
- Managed database raw blob access is refused; uploads carrying secrets are refused until scanning. Live fences precede catalog work except authenticated current-receipt replay. Root/scoped stable idempotency keys distinguish compensation and reconciliation; missing scoped context is an error, while root template failure can fall back with a warning. These keys do not promise exactly-once external effects. [worker.rs:WorkerService::prepare_blob_completion] [worker.rs:WorkerService::check_blob_upload] [worker.rs:WorkerService]

## Side Effects

- Admission/approval/binding/connector/database/definition/egress services call storage/authority/audit ports and emit metrics/spans; durable guarantees depend on implementations. BlobService calls backend PUT/GET/DELETE and catalog operations, including reconciliation cleanup. - Chain commands run the domain engine inside supplied transactions and commit effects; event verification can read secrets/identity providers before inbox admission. Result/event payload services perform bounded backend/store reads and audited current-authority checks. SystemClock reads current time and SystemEntropy supplies nondeterministic tokens/jitter. [chain_progress.rs:ChainCommandService::signal] [events.rs:EventService::verify] [database_results.rs:DatabaseResultService::read_inner] [event_payloads.rs:EventPayloadUseCase] [clock.rs:SystemClock] [entropy.rs:SystemEntropy]

[execution.rs:Engine::run] [maintenance.rs:MaintenanceStore] [loop_progress.rs:LoopProgressStore] [primitives.rs:CollectionStore] [leaf_certification.rs:LeafCollectionSuccessStore]
