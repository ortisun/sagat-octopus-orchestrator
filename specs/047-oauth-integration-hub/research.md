# Research and registers: OAuth resources and a curated integration hub (design 047)

The design is [docs/designs/047-oauth-integration-hub.md](../../docs/designs/047-oauth-integration-hub.md). This file
holds its registers, append-only. Every product or design choice below was taken under the delegation of Owner
decisions 2026-11-20-6 and 2026-11-24-4, weighing every option for the most architectural and business advantage; each
says "delegate (OD-2026-11-24-4)" and why.

## Sources read

- Features 017 (OpenBao authority, recoverable provisioning in `crates/application/src/managed_secrets.rs`, the KV
  version 2 adapter in `crates/infra-secrets/src/openbao.rs` that writes each revision once), 021 (resource types,
  slots, the integration runner, `contracts/resource-types.md` with its `oauth2_client_credentials` scheme), 028 (the
  signed template index, Requirements 028-039 to 028-042, `data-model.md` section 4), 005 (the shim protocol, Decision 111
  on redaction), 009 (egress), 016 (classification), 026 (channel credentials, ADR-0055 rule 11b).
- Constitution 5.0.0 as approved (Owner decision 2026-11-24-2), "Admitted scope" and "Out of scope".
- The Studio's sign-in (OIDC in the browser, `frontend/apps/studio/src/auth`), which makes the API a bearer API.
- Standards: RFC 6749 (OAuth 2.0), RFC 7636 (PKCE), RFC 7009 (revocation), RFC 7523 (JWT client authentication),
  RFC 8414 (server metadata), RFC 9207 (the `iss` parameter), RFC 9700 (OAuth 2.0 security best current practice),
  RFC 8693, RFC 9449, RFC 8705 and RFC 7591 (out of scope, gaps), RFC 8785 (canonical JSON, feature 028).
- Windmill's documented behaviour: OAuth resources connected from its UI and refreshed by the server, tokens given to
  scripts in the resource object, instance-level OAuth client configuration, an open hub of scripts, flows and resource
  types.

## Decisions

| ID | Decision | Reasoning |
|---|---|---|
| D047-001 | A token broker in the control plane is the only component that talks to OAuth endpoints. delegate (OD-2026-11-24-4) | One holder for long-lived credentials that runs no tenant code and already reaches the secret authority; executors would otherwise each hold refresh tokens and race rotations (ADR-0122) |
| D047-002 | Refresh tokens, client secrets and private keys never leave the broker; executors receive the access token only. delegate (OD-2026-11-24-4) | A compromised step loses access when its token expires; Windmill also refreshes server side, but this makes it a rule with canary tests |
| D047-003 | Values in the secret authority of feature 017, one revision per value written once; metadata and the fence in PostgreSQL. delegate (OD-2026-11-24-4) | Feature 017 made OpenBao the authority for new credentials; immutable revisions match its adapter; the fence must be in the database that decides leases |
| D047-004 | Refresh is single-flight by a fenced lease on the credential row, never with a transaction open during the provider call. delegate (OD-2026-11-24-4) | Providers that rotate and detect reuse revoke the family on a race; Principle V forbids holding a transaction over provider input or output |
| D047-005 | A lost rotation moves the credential to `NEEDS_REAUTHORIZATION`; steps fail retryable with `OAUTH_REAUTHORIZATION_REQUIRED`. delegate (OD-2026-11-24-4) | A durable workflow should survive a person reconnecting later; failing permanently (Windmill's behaviour) loses the run, and waiting silently hides the cause |
| D047-006 | PKCE S256 always, even for confidential clients; `state` bound to the starting principal, single use, 10 minutes; `iss` checked when sent. delegate (OD-2026-11-24-4) | RFC 9700 recommends PKCE for every client and defends code injection and mix-up; binding to the principal defeats a forged callback |
| D047-007 | The callback is a Studio page that posts `code` and `state` to the API with the person's bearer token. delegate (OD-2026-11-24-4) | The platform has no cookie session; a cookie only for this would be a second session model to secure. The bearer post binds the callback to the person with the existing model |
| D047-008 | Client registrations per tenant by default; the operator may offer deployment registrations that tenants opt into. delegate (OD-2026-11-24-4) | Per tenant keeps isolation (a tenant's revocation, rate limits and consent screen are its own); Windmill configures OAuth per instance, which a SaaS operator needs for one-click onboarding, so both are offered and the shared one is opt-in |
| D047-009 | Client authentication: `client_secret_basic`, `client_secret_post` and `private_key_jwt`. delegate (OD-2026-11-24-4) | The first two are what providers support; `private_key_jwt` lets a tenant avoid a shared secret where the provider supports it. Mutual TLS is a gap |
| D047-010 | Scripts and activities may declare resources; delivery is the ordinary declared-secret delivery of Principle V with a new gRPC method and a new host call. delegate (OD-2026-11-24-4) | Windmill parity requires scripts to use connected accounts; reusing the declared-set rules keeps one disclosure model. A separate method keeps resource authorization distinct from secret access |
| D047-011 | Access tokens are refreshed on demand within 120 s of expiry, and ahead of time by a pass for credentials used in the last 24 hours; rotating refresh tokens get a keep-alive refresh. delegate (OD-2026-11-24-4) | On-demand alone puts a provider round trip on the path of a step; refreshing every credential wastes requests; some providers expire refresh tokens unused for months |
| D047-012 | Disconnect revokes at the provider at least once, then retires revisions regardless of the outcome. delegate (OD-2026-11-24-4) | Revocation is an external effect that may fail; keeping the revisions after the person asked to disconnect would be worse than an unknown revocation outcome, which is recorded |
| D047-013 | The hub's items live in `hub/` in this repository, with two named reviewers each, validated by the platform's codecs and signed into the release index (feature 028's format). delegate (OD-2026-11-24-4) | Constitution 5.0.0: signed sources only; review and CI in the repository give the same evidence trail as code |
| D047-014 | Hub resource types specialise `http_api` and `graphql` only, with fixed hosts and request presets evaluated by the existing operations. delegate (OD-2026-11-24-4) | Integrations as data add no code path to the integration runner; richer integrations are script templates. Executable connectors per item would each be code in the runner's trust base |
| D047-015 | Imports create immutable tenant-scoped versions with provenance; adoption of a newer version is an explicit resource revision. delegate (OD-2026-11-24-4) | Principle IV: a resource pins what it uses; a hub update must not change running work |
| D047-016 | A revoked hub item cannot be imported; imported versions get a finding; the operator may block new admissions. delegate (OD-2026-11-24-4) | Blocking automatically could stop a tenant's production for a cosmetic revocation; never telling would hide a dangerous one. The operator decides with the index's reason |
| D047-017 | The first curated set: GitHub, Google, Microsoft Graph, Slack, Atlassian, Salesforce, HubSpot, Notion, Zoom and a generic OAuth 2.0 API template. delegate (OD-2026-11-24-4) | The providers Windmill users connect most often across development, office, chat, CRM and project tools; each is a common OAuth 2.0 authorization-code provider with documented endpoints |
| D047-018 | Tenants may author provider definitions (not hub items), with https endpoints under the egress policy. delegate (OD-2026-11-24-4) | Internal identity providers and niche services must be usable without waiting for a release; this is authored content, not a hub source |
| D047-019 | The feature is switched on by the capability `oauth-broker-v1` in the instance registry (the name corrected on 2026-11-26). delegate (OD-2026-11-24-4) | Every replica must deliver resources the same way before a version declares one (ADR-0082) |
| D047-020 | Notification channels of feature 026 keep their own credentials in 0.3.0. delegate (OD-2026-11-24-4) | Moving them now would change an approved draft's security model during the release; a later move is Gap 047-004 |
| D047-021 | Every writer of a credential's state or token revisions increases the fence and compares the value it read; activation also requires the tenant and the state `ACTIVE`; acquire compares the access revision the caller saw, so a refresh already done is not repeated. delegate (OD-2026-11-24-4) | Review round 1 (correctness Blocker 1 and Major 4, security 2, design 2): a disconnect or reconnect during a refresh, and a second caller after an activation, otherwise changed or repeated the grant |
| D047-022 | Token revisions are written as `PENDING` rows before the vault write; a later holder adopts a complete pending refresh revision of an earlier fence before calling the provider. delegate (OD-2026-11-24-4) | Review round 1 (correctness 3, design Blocker 1): the first draft retired a rotated token that was already stored, possibly the only valid one; only the gap from the provider's answer to the vault write now remains |
| D047-023 | Expiry is the acquire statement's database time plus `expires_in`; the provider is called only within 15 s of acquire; vault writes have a 5 s deadline; the lease is extended under the fence when the stores would end late. delegate (OD-2026-11-24-4) | Review round 1 (correctness 2 and 5, security 3): a paused holder or a slow write could otherwise reuse a refresh token after its lease lapsed |
| D047-024 | Two freshness thresholds (deliverable at 60 s, due at 120 s); the proactive refresh of access tokens is dropped; only a keep-alive refresh for providers whose refresh tokens expire when idle remains. delegate (OD-2026-11-24-4) | Review round 1 (zoom-out 3, comprehension 4, style 5): four overlapping thresholds; refresh at delivery is enough for correctness, and the keep-alive keeps idle credentials alive |
| D047-025 | One redirect URI per registration (`/studio/oauth/callback/<registration>`), refused when it does not match the registration of the `state`; `iss` required when the provider definition says the provider sends it. delegate (OD-2026-11-24-4) | Review round 1 (security Blocker 1, design 4): one shared callback allowed mix-up and code injection through an authored provider; RFC 9700 section 4.4 |
| D047-026 | A reconnect keeps the account: a callback with another subject is refused, and moving a resource to another account is a new credential and a new resource revision. delegate (OD-2026-11-24-4) | Review round 1 (security 4, design 3): otherwise anyone who may reconnect could point published workflows at their own account |
| D047-027 | The permissions `oauth:client:manage`, `oauth:credential:manage`, `hub:import`, `hub:publish` and the operator permissions `oauth:offer:manage` and `hub:version:block`. delegate (OD-2026-11-24-4) | Review round 1 (security 5, architecture 9 and 10, design 3): feature 021 expects a manage permission on the credential; imports and blocks need owners |
| D047-028 | The OAuth vault is a separate OpenBao mount with its own policy and a reference type ordinary delivery cannot build; registration secrets are written by the system actor `oauth-broker`, outside the namespace secrets quota. delegate (OD-2026-11-24-4) | Review round 1 (security 9, codebase Blocker 1 and Major 7, correctness 6): custody enforced by addressing; feature 017's provisioning needs a principal, a secret name and the namespace quota, none of which fit an unattended refresh |
| D047-029 | Every broker call is checked against the egress policy of the credential's namespace, intersected with the hub item's fixed hosts. delegate (OD-2026-11-24-4) | Review round 1 (codebase Blocker 2, architecture 11): there is no deployment egress policy; egress is per namespace and denies by default |
| D047-030 | Imports create drafts; a provider or resource type becomes usable only when a holder of `hub:publish` publishes it after the authored checks. delegate (OD-2026-11-24-4) | Review round 1 (architecture Blocker 2, security 5): constitution 5.0.0 admits hub items "imported as drafts under the same publication rules" |
| D047-031 | Hub resource types may narrow any of feature 021's operation kinds and authentication schemes; a host is fixed or a single-label pattern bound once from the token response or the registration; presets encode path variables as single segments and never weaken the effect class. delegate (OD-2026-11-24-4) | Review round 1 (design 5 and 6, security 6, architecture 12): Salesforce, Microsoft and Atlassian need bound hosts or path values; path injection; feature 021's Decision 021-004 admits every operation kind |
| D047-032 | Revocations carry a class; a `security` revocation blocks new admissions until an operator lifts it; a signed revocation feed, optional, makes a revocation effective within 24 hours; an operator may block a digest directly. delegate (OD-2026-11-24-4) | Review round 1 (security 7, design 10): a revoked preset otherwise kept running until operators upgraded |
| D047-033 | Scripts receive resources through the worker gRPC `ResolveDeclaredResources`, as they receive secrets; mid-run asks go through a `resource` host call that grows the redaction set; re-asks are counted in the database; activities that declare resources are leased only at this design's protocol minor. delegate (OD-2026-11-24-4) | Review round 1 (codebase Blocker 3 and Major 4, architecture 8, correctness Nit 12, zoom-out 7): the runner REST surface carries no secrets; a fixed redaction set; counts across control planes; old sessions |

| D047-061 | Answers to the security re-read of 2026-11-26. Retired and abandoned refresh revisions are destroyed in the vault only and never revoked at the provider (a provider that returns the same value, or revokes the grant on any token's revocation, would lose the live grant); the provider is called on a disconnect, and for an abandoned revision only with a different value hash and `revocation: "per-token"`. The sweeper revokes and destroys `PENDING` rows of disconnecting or disconnected credentials and stale ones, downgrading and auditing the outcome. Requests in flight are unexpired leases and broker-call rows counted under the window row's lock, never a counter; a deployment registration's tenant share is 1 in flight and an even share per second, and every broker call counts. Opt-in has state predicates, a column grant and a trigger keeping `WITHDRAWN` final. A credential and an authorization request name their registration through two foreign-keyed columns, exactly one set. `hub_record_revocation` only inserts `INDEX` blocks. delegate (OD-2026-11-24-4) | Targeted security re-read of 2026-11-26, findings 1 to 7 |
| D047-062 | The sweeper revokes at the provider only `PENDING` rows of disconnecting or disconnected credentials, and an unmarked one only after the lease and store deadlines; a stale `PENDING` row of a live credential is adopted by the next acquire and, once replaced, destroyed in the vault only, because it may hold the only valid refresh token or the live value. delegate (OD-2026-11-24-4) | Security confirmation of 2026-11-26, findings 1 and 2 |
| D047-063 | The adopt step and the sweeper claim a row's write-once vault reference with a tombstone (a check-and-set write that succeeds only where nothing is written) before abandoning or closing an unmarked row, so a holder suspended past every deadline cannot write a token that nothing tracks. Rejected: measuring the store deadline on `CLOCK_BOOTTIME` alone (a suspension between the check and the write still escapes it). delegate (OD-2026-11-24-4) | Security confirmation 2 of 2026-11-26, finding 1 |
| D047-064 | A tombstone carries a fixed payload and custom metadata that a probe reads as claimed, never as a token, so a claim interrupted before the abandon mark is finished by the next probe instead of activating the tombstone; destroying a revision keeps the key's metadata so its reference stays unwritable. Recorded in the data model, which the build reads; the design's "present when probed" means a token present. delegate (OD-2026-11-24-4) | Security confirmation 3 of 2026-11-26, finding 1 |
| D047-065 | Answers to the EGM stages of 2026-11-26 (structural, writing, implementation readiness, codebase details) made in the text before approval: the redirect URI built from a new setting `SAGAT_STUDIO_ORIGIN`, never a request header; the `resource` host call in all five sandbox languages, with the TypeScript and Python shims in `crates/infra-sandbox/shims/`; migrations after `20270210000100`; the OpenBao files of feature 017 and `infra/openbao/`; feature 028's domain, store, routes, Studio and CLI surfaces extended instead of new `hub` ones; feature 021's ordinary-delivery checks and protocol-minor gating reused; `workflow.schema.json` and an intermediate-representation fragment contract; a fourth gRPC limit class; the permissions in `Permission::ALL`; the delivery tasks gated on constitution 5.1.0; the feature 021 and 028 tasks that come first; feature 028's table changes moved to Task 047-13; the withdrawn-offer and probe tests placed; both client errors counted toward `BROKEN`; a sliding 60-minute window for re-asks; the sweeper's 60 s wait. Requirement identifiers stay in words, as constitution 4.7.0 requires (the template's `FR-` form is the old one). delegate (OD-2026-11-24-4) | EGM stages of 2026-11-26 |
| D047-066 | Answers to the security read of the EGM fixes (2026-11-26): the acquire locks one window row per registration and per tenant in its own statements before the counting update, so a later snapshot sees every committed acquire; the `resource_delivery` class is shed at the `discovery` threshold or below, has process and per-tenant caps and never waits holding a place; client errors to a code exchange fail only that connection and never count toward `BROKEN`; a trigger sets `refresh_stops_at` and freezes a withdrawn offer; a holder refused by a tombstone revokes its token and a tombstoned row records `UNKNOWN`; re-asks keep their last 30 times for a sliding window. delegate (OD-2026-11-24-4) | Security read of 2026-11-26, findings 1 to 6 |

## Gaps

| ID | Gap | State |
|---|---|---|
| G047-001 | Token exchange (RFC 8693) to narrow a token per step is not offered; a step receives the credential's whole granted scope | Open (later release) |
| G047-002 | Sender-constrained tokens (DPoP, RFC 9449; mutual-TLS-bound tokens, RFC 8705) and mutual-TLS client authentication are not offered | Open |
| G047-003 | Dynamic client registration (RFC 7591) is not offered; registrations are made by hand at the provider | Open |
| G047-004 | Notification channels of feature 026 could hold their credentials as OAuth credentials of this design (Slack, Microsoft Teams) | Open (after 0.3.0) |
| G047-005 | The proactive window (5 minutes), the use window (24 hours) and the keep-alive interval per provider are estimates | Open (measure) |
| G047-006 | Runs against the real providers of the curated set need accounts and credentials that only the owner can create; until then the recorded-response tests are the evidence | Open (owner's credentials) |
| G047-007 | The window between a provider's answer with a rotated refresh token and its write to the OAuth vault cannot be closed by the platform; a crash there may need a reconnect (journey 5 of the design). The window after the vault write is closed by adoption (Decision 047-022) | Accepted, stated |
| G047-008 | A broker-side proxy that injects tokens into scripts' and activities' requests, so that no executor holds a token, is not offered in 0.3.0; a raw token can do anything its scopes allow | Open (later release) |
