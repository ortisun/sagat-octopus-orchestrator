# Contract design for feature 016

**Status: designed, not built.** Nothing below is deployed. The canonical contracts stay in
`specs/001-platform-foundation/contracts/` (`workflow.schema.json`, `openapi.yaml`); the changes listed
here are made there by the tasks of `tasks.md` (T016-006, T016-008, T016-060), never by this document. `worker.proto`
and `events.asyncapi.yaml` do not change.

## 1. Workflow IR (`workflow.schema.json`)

The document stays `sagat-octopus-orchestrator.io/v1`; the changes are additive keys (ADR-0032 keeps
additive keys inside `v1`, and the base node schema already allows extra keys, so an engine without this
feature ignores them).

### 1.1 The annotation

```json
"x-sagat-classification": "public" | "internal" | "pii" | "secret"
```

A JSON Schema 2020-12 annotation keyword (unknown keywords are annotations and do not change
validation; T016-013 proves that the pinned `jsonschema` 0.58 agrees). Its value is a string from the
four levels, case-sensitive.

### 1.2 Carriers (the only places it is read)

| Carrier | Where | Exists today | Governs |
|---|---|---|---|
| `inputSchema` | document root | yes (`type: object`, optional) | the run input (`source: "input"`) |
| `outputSchema` | document root | yes (`type: object`, optional) | the run result (`source: "result"`) |
| `outputSchema` | `activity`, `script`, `waitEvent`, `child` node | **new**, optional, `type: object` | the payload of that node's `step.completed`, `wait.satisfied` or `reconciliation.concluded` event (`source: "journal"`) |

Not carriers, and an annotation there is refused (`CLASSIFICATION_NOT_APPLICABLE`): the declared state
and the argument and result schemas of Query and Update (feature 014, ADR-0031), `humanApproval.formSchema`,
trigger filters, any other node, and `metadata`. A carrier is self-contained: a `$ref` must be a pointer
beginning `#/` that resolves inside the same carrier (`#/$defs/...`, `#/properties/...`); no remote,
absolute, anchor-by-name or cross-carrier reference.

Schema diff for `$defs` (shape only; the carrier schema is a free-form object, as today):

```json
"activity":  { "allOf": [ {"$ref": "#/$defs/base"}, { "properties": { "outputSchema": {"type": "object", "maxProperties": 64} } } ] }
"script":    { "properties": { "outputSchema": {"type": "object", "maxProperties": 64} } }
"waitEvent": { "properties": { "outputSchema": {"type": "object", "maxProperties": 64} } }
"child":     { "properties": { "outputSchema": {"type": "object", "maxProperties": 64} } }
```

The JSON Schema of the IR checks only that `outputSchema` is an object. The codec (`crates/infra-ir`)
checks the rest (section 1.4). `docs/reference/workflow-document.md` is regenerated by
`cargo test -p sagat-tests --test contract_developer_experience` with `SAGAT_DOCS_BLESS=1`.

### 1.3 Semantics (normative; mirrored in `data-model.md` and `research.md` D264-D268)

1. Order: `public < internal < pii < secret`. "Stricter" means greater.
2. The root of a carrier without an annotation is `pii`.
3. An annotated schema node sets the level of the values it governs; an unannotated declared node
   inherits the effective level of its parent.
4. A value no schema node declares is at least `pii` (stricter of inherited and `pii`).
5. Where several subschemas govern one location (`allOf`, `anyOf`, `oneOf`, `$ref`), the strictest
   annotation among all of them applies, without choosing a branch from the data.
6. Supported keywords: `type`, `properties`, `additionalProperties`, `items`, `prefixItems`, `$ref`
   (inside the carrier), `$defs`, `allOf`, `anyOf`, `oneOf`. An annotation under any other applicator
   (`patternProperties`, `if`/`then`/`else`, `dependentSchemas`, `contains`, `propertyNames`, `not`,
   `unevaluated*`, `$dynamicRef`) is refused; the keyword itself may appear, and what it alone governs
   is undeclared (rule 4).
7. A declared child never lowers the level. Inline or through `$ref`, a lower declaration is a
   publication error; the evaluator still clamps (`max`) as defence in depth.
8. A node with an annotation but no `type` governs every type at that location.

Worked example (the corpus of `tests/contract/payload-classification/fixtures/`):

```json
"inputSchema": {
  "type": "object",
  "x-sagat-classification": "public",
  "additionalProperties": false,
  "properties": {
    "orderId":  {"type": "string"},
    "amount":   {"type": "number", "x-sagat-classification": "internal"},
    "customer": {
      "type": "object",
      "x-sagat-classification": "pii",
      "additionalProperties": false,
      "properties": {
        "name":      {"type": "string"},
        "email":     {"type": "string", "format": "email"},
        "cardToken": {"type": "string", "x-sagat-classification": "secret"}
      }
    }
  }
}
```

Effective levels: `/orderId` public (inherited), `/amount` internal, `/customer` pii, `/customer/name`
and `/customer/email` pii (inherited), `/customer/cardToken` secret. `validate` reports one
`CLASSIFICATION_INHERITED_OPEN` warning, for `/orderId`.

### 1.4 Publication and `validate` findings

`validateWorkflowDraft` returns these as `DefinitionProblem` (`severity`, `code`, `message`, `path`);
`publishWorkflow` refuses a document with any error as `422 VALIDATION_FAILED` with
`details.reason = "CLASSIFICATION"` and `details.issues[] = {path, code, message}` (at most 20).
Messages come from a closed table and never quote the document beyond a clipped fragment.

| Code | Severity | When |
|---|---|---|
| `CLASSIFICATION_INVALID_LEVEL` | error | the value is not one of the four strings |
| `CLASSIFICATION_LOOSENED` | error | a declared node is less strict than its effective parent (including an unmarked `pii` root) |
| `CLASSIFICATION_UNSUPPORTED_KEYWORD` | error | an annotation under a keyword outside rule 6 |
| `CLASSIFICATION_UNRESOLVED_REF` | error | a `$ref` that is not a pointer inside the carrier, or does not resolve |
| `CLASSIFICATION_NOT_APPLICABLE` | error | an annotation outside a carrier |
| `CLASSIFICATION_TOO_COMPLEX` | error | a carrier over 64 KiB, nesting over 32 or more than 1,000 `$ref` expansions |
| `CLASSIFICATION_INHERITED_OPEN` | warning | a declared child with no annotation under an annotated `public` or `internal` container |

A carrier that carries no annotation and is not a node-level `outputSchema` is not compiled at
publication, so every document accepted today is accepted unchanged. A node-level `outputSchema`, and
any carrier that carries an annotation, must compile (no network, no file; patterns use the linear-time
engine, as `crates/infra-schema` does) or the document is refused with `SCHEMA` and the pointer.

### 1.5 Pinning

`workflow_versions.classification_rules` (smallint, `0` for versions published before this feature,
`1` for the rules of this document). The runtime selects the interpreter by this number. A release that
changes the interpretation adds `2` and publishes new versions under it; it never reinterprets `1`.

## 2. OpenAPI (`openapi.yaml`)

All additions are new operations and new schemas, `x-implemented: '016'`. Existing operations,
schemas and responses are unchanged, except the three event reads of section 2.4 (a breaking change,
owner decision D291) and the documented `permissions` examples of `AuthContext`,
which gain `payload:read-internal` for the roles that hold it.

### 2.1 `POST /runs/{runId}/payload-disclosures` (`discloseRunPayload`, tag Runs)

Needs `run:read`. Request body, at most 1 KiB, unknown fields refused:

```json
{ "source": "input" }
{ "source": "result" }
{ "source": "journal", "sequence": 42 }
{ "source": "input", "reveal": ["pii"] }
```

`reveal` is optional, holds at most the single value `"pii"`. `sequence` is only for `journal`, a
positive int64. Canonical namespace API admission is charged once after authorization and run resolution
(`ApiOperation::PayloadDisclose`, permissions `[run:read]`). The event reads keep `ApiOperation::EventRead`.

Response `200`, headers `Cache-Control: private, no-store`, `X-Trace-Id`, `X-Request-Id`:

```typescript
type Selector = { source: "input" } | { source: "result" } | { source: "journal"; sequence: number };
type Level = "public" | "internal" | "pii" | "secret";

type Provenance = {
  runId: string;
  runVersion: number;            // version observed with the selected record, as in ADR-0028
  selection: Selector;
  nodeId?: string;               // only when present on the selected journal event
  attempt?: number;
  policy: "classified-v1";
  caller: { disclosedLevels: ("public" | "internal" | "pii")[];  // the levels this answer was built to contain
            revealPii: "granted" | "not_granted";               // grant exists and the role holds payload:read-internal
            revealed: boolean };                                // this answer was built with reveal (about the caller only)
};

type Schema = {                  // provenance of the classification
  carrier: "inputSchema" | "outputSchema" | "nodeOutputSchema";
  versionNumber: number;         // the pinned workflow version
  rules: 1;                      // classification rules version
};

type Node =
  | { kind: "value"; level: Exclude<Level, "secret">;
      type: "string" | "number" | "boolean" | "null"; value: string | number | boolean | null;
      valueTruncated?: true; length?: number }           // length in bytes of the original string
  | { kind: "container"; type: "object" | "array"; level: Exclude<Level, "secret">;
      childCount: number; omittedChildren: number; children: Child[] }
  | { kind: "withheld"; type: "object" | "array" | "string" | "number" | "boolean" | "null";
      level: "internal" | "pii" | "secret";
      reason: "LEVEL_NOT_PERMITTED" | "REVEAL_NOT_REQUESTED" | "SECRET" };   // callers with run:payload:inspect only

type Child = { ordinal: number; name?: string; node: Node };   // name: a declared property, or a disclosed value's key

type Disclosure = Provenance & (
  | { kind: "disclosed"; schema: Schema; sizeBytes: number; truncated: boolean; tree: Node }
  | { kind: "structure-only"; schema?: Schema; sizeBytes: number; truncated: boolean;
      reason: "NO_SCHEMA" | "SCHEMA_MISMATCH" | "LEGACY_VERSION" | "SCHEMA_UNUSABLE";
      tree: PayloadStructure }                                       // the ADR-0028 type; run:payload:inspect only
  | { kind: "external"; sizeBytes: number; contentKind: "json" | "text" | "binary" | "other";
      reason: "EXTERNAL_CONTENT_NOT_INSPECTED" }
  | { kind: "unavailable"; reason: "NO_RETAINED_PAYLOAD" | "UNSUPPORTED_FORMAT" | "NOT_DISCLOSABLE";
      sizeBytes?: number }
);
```

Rules of the answer:

- `structure-only` appears only for a caller that holds `run:payload:inspect`; every other caller gets
  `unavailable` with `NOT_DISCLOSABLE` for the same situations, so that the state of a payload (valid,
  invalid, schema-less, legacy) is not an oracle for them.
- For a caller without `run:payload:inspect`, withheld nodes are omitted and `childCount` counts the
  children returned; for a holder, `childCount` is the true count and withheld children appear.
- `name` is present for a child declared in `properties`, and for an undeclared key only when its value
  node is `value` or `container`. A withheld undeclared key has `ordinal` only.
- Arrays have no `name`; `ordinal` is the index.
- Limits: depth 16, 1,024 nodes, 128 children per container, string cut at 4,096 bytes (`valueTruncated`,
  `length`), 128 KiB of disclosed string bytes, response 256 KiB. At a limit the container keeps its
  `childCount`, sets `omittedChildren`, and the top-level `truncated` is `true`; traversal is deterministic.
- A `container` of level L is returned only if the caller may read level L; children are judged on
  their own level, which is never lower.

#### Audience matrix

The rows of SC-016-002. "inspect" means the caller also holds `run:payload:inspect`; "grant" means
`payload:reveal-pii` in the run's namespace (with `payload:read-internal` held by the role); "reveal"
means the request carries `reveal: ["pii"]`. A cell says what the answer contains for that level.

| Role (default permissions) | `public` | `internal` | `pii` | `secret` |
|---|---|---|---|---|
| `viewer` | value | omitted | omitted (a grant is refused for this role) | omitted |
| `developer` | value | value | omitted; value with grant and reveal | omitted |
| `operator` (inspect) | value | value | withheld `LEVEL_NOT_PERMITTED`; with grant and no reveal `REVEAL_NOT_REQUESTED`; value with grant and reveal | withheld `SECRET` |
| `admin` (inspect) | value | value | as `operator` | withheld `SECRET` |
| `worker`, `runner` | `403` | `403` | `403` | `403` |

`reveal` without a grant, or by a role that lacks `payload:read-internal`, is `403` (`PII_REVEAL_NOT_GRANTED`), not an empty answer. A
`secret` node is never `value`, whatever the role, grant or request.

Errors (the closed `Error.code`; `reason` in `details`):

| Status | `code` | `details.reason` | When |
|---|---|---|---|
| 400 | `BAD_REQUEST` | | malformed JSON, unknown field, body over 1 KiB (413 `PAYLOAD_TOO_LARGE` as ADR-0028) |
| 401 | `UNAUTHENTICATED` | | no or bad credentials |
| 403 | `FORBIDDEN` | | no `run:read` |
| 403 | `FORBIDDEN` | `PII_REVEAL_NOT_GRANTED` | `reveal` requested without `payload:reveal-pii` in the namespace |
| 404 | `NOT_FOUND` | | missing or foreign run, missing sequence (opaque) |
| 422 | `VALIDATION_FAILED` | | a selector or `reveal` value outside the schema |
| 429 | `RATE_LIMITED` / `QUOTA_EXCEEDED` | | ADR-0027 admission, with bounded `Retry-After` |
| 503 | `UNAVAILABLE` | | store or audit unavailable (no value is returned) |

Remediation rows are added to `ErrorCode::remediation` in `crates/api-http/src/error.rs` for
`PII_REVEAL_NOT_GRANTED`, `CLASSIFICATION`, `UNKNOWN_SUBJECT`, `ROLE_CANNOT_REVEAL` and `GRANT_LIMIT`; each is a fixed sentence.

### 2.2 Reveal grants (tag Governance)

| Operation | Path | Permission | Behaviour |
|---|---|---|---|
| `listPayloadRevealGrants` | `GET /namespaces/{namespaceId}/payload-reveal-grants` | `membership:manage` | the subjects granted, with `grantedBy` and `grantedAt`; paged by cursor |
| `grantPayloadReveal` | `PUT /namespaces/{namespaceId}/payload-reveal-grants/{subject}` | `membership:manage` | idempotent; `200` with the grant; audited `payload.reveal_granted` in the same transaction; `422 UNKNOWN_SUBJECT` when the tenant has no such membership; `422 ROLE_CANNOT_REVEAL` when the subject's role lacks `payload:read-internal`; `429 QUOTA_EXCEEDED` `GRANT_LIMIT` over 256 |
| `revokePayloadReveal` | `DELETE /namespaces/{namespaceId}/payload-reveal-grants/{subject}` | `membership:manage` | `200` with an empty object; `404` when there is no grant; audited `payload.reveal_revoked` |

`{subject}` uses the same pattern as `WorkerSubject`. Namespace admission is charged as for the sibling
`worker-bindings` operations. The mechanism is the owner's decision of 2026-10-17 (D275). The subject may
be the caller (D295); the audit record shows actor and subject.

### 2.3 Other additions

- `PermissionName` examples and the documented list of `AuthContext.permissions` gain
  `payload:read-internal`. `payload:reveal-pii` is not listed there: it is namespace-scoped, so a caller
  learns whether it holds it from `Disclosure.caller.revealPii`.
- `DefinitionProblem.code` description gains the `CLASSIFICATION_*` codes. `Validation` gains the optional
  `classification` array of `{carrier, nodeId?, path, level, declared}` (the effective level of each
  declared location, `declared` false when inherited), at most 500 entries, and `classificationTruncated`.
- `DiffFinding.code` description gains `CLASSIFICATION_RELAXED` and `CLASSIFICATION_TIGHTENED`
  (attention, not breaking).
- `Error.details.reason` description gains the five reasons above.

### 2.4 Event inbox and dead letters (US08, `x-implemented` stays `'004'`, marked `x-extended: '016'`)

Existing operations whose responses change. They need `event:read` as today; the reveal needs, in
addition, `payload:read-internal` and the grant of `payload:reveal-pii` in the namespace of the event or
connector.

| Operation | Path | Change |
|---|---|---|
| `getInboxEvent` | `GET /namespaces/{namespaceId}/events/{source}/{eventId}` | optional query `reveal` (`pii`); `data` conditional; new `dataDisclosure`, `dataSizeBytes`, `dataStructure` |
| `getConnectorDeadLetter` | `GET /namespaces/{namespaceId}/connectors/{connectorId}/dead-letters/{deadLetterId}` | optional query `reveal` (`pii`); `body` and `headers` conditional; new `bodyDisclosure`, `bodySizeBytes`, `bodyStructure`, `headerCount` |
| `listConnectorDeadLetters` | `GET .../dead-letters` | never returns `body` or `headers`; same new fields per item; `reveal` is not a parameter and is ignored |

Schemas (shape; the rest of `InboxEvent` and `DeadLetter` is unchanged):

```typescript
type InboxEvent = {
  eventId: string; source: string; type: string; subject?: string; correlationKey?: string;
  occurredAt?: string; receivedAt: string; expiresAt: string;
  status: "PENDING" | "DISPATCHED" | "DEAD"; attempts: number; lastError?: string; dispatchedAt?: string;
  deliveries: EventDelivery[];
  dataDisclosure: "revealed" | "structure-only";   // required (new)
  dataSizeBytes: number;                           // required (new): bytes of the stored payload
  data?: object;                                   // present only when dataDisclosure is "revealed"; was required
  dataStructure?: PayloadStructure;                // present only when "structure-only"; the ADR-0028 type
};

type DeadLetter = {
  id: string; position: string; reason: "NO_EVENT_TYPE" | "BAD_ENVELOPE" | "NOT_A_JSON_OBJECT" | "TOO_LARGE" | "EVENT_ID_REUSED";
  truncated: boolean; receivedAt: string;
  bodyDisclosure: "revealed" | "structure-only";   // required (new)
  bodySizeBytes: number;                           // required (new): bytes kept (at most 64 KiB)
  headerCount: number;                             // required (new)
  headers?: Record<string, string>;                // present only when revealed; was required
  body?: string;                                   // present only when revealed; was required
  bodyStructure?: PayloadStructure | { kind: "opaque" };   // when "structure-only"
};
```

Rules:

- `reveal` accepts only `pii`; another value is `422 VALIDATION_FAILED`. Without it, or without the grant, the
  answer is the structure answer. With it and without the right, the answer is `403 FORBIDDEN` with
  `details.reason = PII_REVEAL_NOT_GRANTED` (no new reason, no new `Error.code`).
- A revealed answer carries every value of the event or letter, because events have no classification
  carrier: the data is `pii` as a whole (D291, G291). No `secret` handling exists for events.
- The structure is the ADR-0028 `PayloadStructure` with its bounds (depth 16, 256 nodes, 32 children), built
  by the existing `JsonPayloadProjector`; it holds no key and no scalar. A dead-letter body that is not
  bounded JSON, or is cut at 64 KiB mid-document, is `{"kind": "opaque"}`.
- Both answers carry `Cache-Control: private, no-store`. The Studio, the CLI and the SDKs do not read these
  fields today (checked in `frontend/apps/studio/src`, `apps/cli/src`, `sdks/*`); the operations of this
  table are read by API clients.
- Compatibility: this is a **breaking change** for any client that read `data`, `body` or `headers` as a plain
  `event:read` holder (G292). `data`, `body` and `headers` leave the `required` lists; the three new
  disclosure fields join them. The OpenAPI descriptions, `docs/reference/api.md`, `docs/runbooks/events.md` and
  the release notes state it.

Audience for events and dead letters ("grant" means `payload:reveal-pii` in the event's namespace):

| Caller | no `reveal` | `reveal=pii` |
|---|---|---|
| any `event:read` holder, no grant | structure | `403 PII_REVEAL_NOT_GRANTED` |
| `viewer` with a grant (inert) | structure | `403 PII_REVEAL_NOT_GRANTED` |
| `developer`, `operator`, `admin` with a grant | structure | values, audited |
| no `event:read` (`worker`, `runner`) | `403` | `403` |
| another tenant's event, connector or letter | `404` | `404` |

## 3. Audit

| Action | Resource | Written when | Reason (server-built) | Repeats |
|---|---|---|---|---|
| `payload.disclosed` | run | a disclosure returned at least one `internal` value | `classified-v1:input`, `classified-v1:result`, `classified-v1:journal:<sequence>` | collapse 300 s |
| `payload.pii_revealed` | run; for events `ResourceType::Event` (id `source/event id`, reason `event-data:reveal=pii`); for a dead letter `ResourceType::Connector` (reason `dead-letter:<letter id>:reveal=pii`) | a reveal returned at least one `pii` value, or an event or letter value | run: the same with `:reveal=pii` | never collapse |
| `payload.reveal_denied` | run, event or connector, as above | `reveal` without a grant | `permission` | collapse 300 s, best effort |
| `payload.reveal_granted` | payload reveal grant (`ResourceType::PayloadRevealGrant`, id `namespace-id/subject`, as `Worker`) | a grant is created | `granted` | none |
| `payload.reveal_revoked` | payload reveal grant | a grant is removed | `revoked` | none |

A `public`-only disclosure is not audited per request (volume); it is counted by metric. No record
holds a value, key, digest, schema, free text or secret. `payload.pii_revealed` and the grant actions
are visible to `audit:read`; `CrossTenantAccessDenied` stays withheld from the tenant as today.

## 5. Compatibility

- A server without this feature answers the new paths `404 ROUTE_NOT_FOUND`; clients treat that as "not
  supported".
- A version published before this feature has `classification_rules = 0`: no annotation is read, every
  disclosure answers `structure-only/LEGACY_VERSION` (operators) or `unavailable/NOT_DISCLOSABLE`.
- The new node `outputSchema` is ignored by an older engine; publication on a newer server then pins
  rules `1`, and the document is only meaningful to a server that has this feature (the same document
  published to an older server discloses nothing, which is the safe direction).
- Events: older clients keep a working call but receive the structure answer (FR-016-028, G292); the three
  fields they depended on are conditional. A server without this feature ignores `reveal` and returns the
  values as before.
- No change to `worker.proto`, no change to the SDK wire protocol minor.
