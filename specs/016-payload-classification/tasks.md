# Tasks: Per-field payload classification

**Input**: `spec.md`, `plan.md`, `research.md`, `data-model.md`, `contracts/README.md`, `quickstart.md`.
**Scope**: all of ADR-0033 for run payloads (input, result, step outputs) and, by the owner's decision of
2026-10-17, the restriction of event values (US08). Implementation is in progress on the approved
integration branch. Focused evidence and remaining gaps are recorded in
`tasks/project-completion/integration-notes.md`; unchecked tasks still require their complete gates.
T016-001 closes when this specification is merged. A task is ticked only with
the evidence that closes it (a named test that passed, a command and its result). Tests precede
implementation within each phase. IDs are feature-scoped per the constitution. `[P]` marks tasks that
touch disjoint files and can run in parallel; `[USnn]` ties a task to a user story.

> **Evidence paths.** References to `tasks/project-completion/` in this repository point at the working and
> evidence tree of the Codex session that built this work. That tree (about 1.7 million lines of raw command
> output, source snapshots and drafts) is deliberately not in git; it is preserved outside the repository
> (local ref `handoff/016-project-completion-20261024`). A tick or a claim that cites only such a path is
> historical until the named command is rerun in this tree.

**Decisions**: the owner answered P1 to P4 on 2026-10-17 (T016-002): a per-namespace grant list, event
values restricted now, the restrictive readings of ADR-0033, audited self-grant. No task waits on a product
question. IDs T016-057 to T016-065 (US08) were added after the first numbering and sit in "Phase 5b" by
dependency (they need the grant table and the reveal path), so the IDs there are not in numeric order of
the phases; existing IDs were kept so that references stay valid.
