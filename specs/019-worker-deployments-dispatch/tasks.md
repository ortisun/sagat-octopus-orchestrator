## Build slices (2026-11-24)

Two builders work in parallel, one per lane. A lane owns its crates for the whole feature, so the two lanes never
change the same crate, app, SDK or suite at the same time. Each slice is one pull request: its tasks are written
test first, its gate test must pass on the merged tree, and the next slice of the same lane starts after it merges. A
slice that names a dependency on the other lane or on another feature waits for that work to be merged. No task is
ticked by this section; each is ticked only with its own evidence.

**Lane A, the server**, owns `crates/domain`, `crates/application`, `crates/infra-postgres`, `crates/api-grpc`,
`crates/api-http`, `crates/scheduler`, `crates/infra-ir`, `apps/execution-engine`, `apps/control-plane`, the canonical
contracts in `specs/001-platform-foundation/contracts/`, and the suites `contract_rest_worker_deployments_dispatch`,
`contract_grpc_worker_deployments_dispatch`, `integration_worker_deployments_dispatch`,
`fault_worker_deployments_dispatch`, `e2e_worker_deployments_dispatch`, `perf_worker_deployments_dispatch`,
`integration_claim_transition_efficiency`, `integration_schedules_bulk_operations` (its `REPIN` case),
`contract_workflow_primitives` and the battery `contract_rest_security_multitenancy`.

**Lane B, the edges**, owns `crates/telemetry`, `crates/infra-connectors`, `crates/infra-sandbox`, `apps/sandbox-runner`,
`apps/cli`, `runners/*`, the six SDKs (`sdks/typescript`, `sdks/go`, `sdks/python`, `sdks/dotnet`, `sdks/java`,
`sdks/rust`), `frontend/apps/studio`, `examples/`, the runbooks and reference documents, and the suites
`sdk_conformance`, `contract_developer_experience`, `integration_inline_code_sandbox` and
`integration_inline_code_sandbox_containers`.

Lane A uses metric names and the push adapter that lane B publishes, and lane B builds against the contracts and
server slices lane A merged; neither edits the other's crates. A metric name lane A needs and lane B has not defined is
a lane B change first.
