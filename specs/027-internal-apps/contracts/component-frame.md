# Custom component frame contract — feature 027 (draft)

Protocol name: `sagat-app-component/1`. Applies to every `custom` component. Not implemented. The
host is the platform's app runtime (Studio page or apps-origin page); the frame is the component's
document. The frame is untrusted.

## Origin and capability

- Frames are served only from the **component sandbox origin** (`SAGAT_APPS_SANDBOX_ORIGIN`). It is
  distinct from the Studio, apps and public-page origins and serves nothing but
  `GET /v1/app-runtime/frames/{frameToken}`; every other path is `404`. Every response of that host,
  at every status, carries the sandbox headers, so a defect that drops a header on an error path is
  caught by the header contract test and, even then, would run author code on an origin that holds no
  token and no trusted page. Without a sandbox origin, custom components are unavailable.
- `frameUrl` comes from `mintAppComponentFrame` per mount. It is single-use (consumed by the first
  load), valid 60 s until then, never past the session, and bound to one pinned component version.
  The host mints a new one only when it mounts the component again after a teardown it initiated.

## Frame element and document

- Element: `<iframe sandbox="allow-scripts" src="<frameUrl>" title="<component title>"
  referrerpolicy="no-referrer" allow="" loading="lazy">`. Never `allow-same-origin`,
  `allow-popups`, `allow-forms`, `allow-modals`, `allow-downloads`, `allow-top-navigation*`.
- Document: generated by the server from the pinned component version:
  `<!doctype html><meta charset="utf-8"><style>{style}</style><script>{shim}</script><script>{bundle}</script>`.
  The CSP hashes are computed over the exact bytes between the tags; the bundle cannot close its
  tag because uploads containing `</script`, `</style` or `<!--` in any ASCII letter case are refused.
- Headers: see the plan's security header table (CSP `sandbox allow-scripts`, `connect-src 'none'`,
  `frame-ancestors` = Studio and apps origins, `private, no-store`, `no-referrer`).
- The document has an opaque (`null`) origin: no cookies, storage, IndexedDB, service worker, or
  same-origin access to the host. It receives no session or bearer token.

## Messages

All messages are plain JSON objects `{ "protocol": "sagat-app-component/1", "type": …, … }` sent with
`postMessage`. The host sends to `iframe.contentWindow` (target origin `*`, because the frame's
origin is opaque) and accepts a message only if `event.source === iframe.contentWindow` and the
frame has not reloaded. Size ≤ 64 KiB (hard 256 KiB); rate ≤ 20/s (hard 50/s) per frame.

| Direction | `type` | Body | Rules |
|---|---|---|---|
| host → frame | `init` | `props` (validated against `propsSchema`), `theme` (snapshot of the token custom properties, `colorScheme`, `forcedColors`), `locale` | Sent once after `ready`; `pii` props only where `allowPii` is declared and the value was disclosed to the viewer; `secret` never; never above the version's `frame_level` for that component (author-side rule below) |
| host → frame | `props` | changed `props` | Same rules as `init` |
| frame → host | `ready` | — | First message; others before it are dropped |
| frame → host | `event` | `name` (declared in `eventsSchema`), `payload` (validated) | Maps to `setState` or `invoke` per the document; a write `invoke` opens the host's confirmation |
| frame → host | `resize` | `height` in CSS px, 1–4,096 | Debounced by the host |
| frame → host | `error` | `code` ≤ 64 ASCII | Shown as "Component failed" with the code; never a free-text message |

## Author-side rule and frame-originated values (D1399)

- At publication the codec computes, by data flow over references, the highest level any value can
  have when it reaches each component (`frame_level`). The app-version publisher and the uploader of
  that component version must hold the rights for it in the namespace (`run:read`;
  `payload:read-internal` for `internal`; the reveal grant for `pii`), else `COMPONENT_AUTHOR_LEVEL`.
  Session creation re-checks the uploader; if the rights are gone, the component is unavailable.
- Values a frame sets (`setState`) or sends (`event.payload`) are **frame-tainted**, and so is anything
  derived from them. Publication refuses a tainted reference in the target or arguments of a binding
  whose result can reach any frame, and in the target or arguments of any `update` or `start` binding
  (`FRAME_TAINTED_FLOW`). A component can therefore trigger a fixed read, or ask the host to confirm a
  write whose arguments come from built-in components, but it can neither steer which data it receives
  nor choose what is written.

## Errors and teardown

Anything else, an invalid payload, a size or rate violation, a second `load` event of the frame
(self-navigation or reload) or a missing `ready` within 10 s makes the host remove the frame, stop
sending data and show the component as failed. Component events cannot set another component's
values except through `setState` into the component's own declared state key.

## What the frame contract does not guarantee (G1361)

The browser cannot stop a frame from sending data it received through channels outside CSP
(WebRTC data channels, self-navigation to a URL carrying data, DNS prefetch). Values passed to a
component must be treated as disclosed to the component's author. The host minimizes them by the
classification rule above; it does not make the frame a confidentiality boundary.
