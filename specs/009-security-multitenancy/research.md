# Research & Decisions: Security, isolation and multi-tenant governance

## Main decision

RBAC policy port in the application layer, verified claims, query filters + defenses-in-depth, sandbox executor without privileges and egress proxy.

## Rationale

Protect tenant workloads, secrets and untrusted code execution before offering inline scripts. The decision respects the recovery, auditability, security and versioning properties defined in the Constitution.

## Alternatives considered

1. **Generic ad hoc queue-based solution:** rejected as the sole durability mechanism, since message delivery is not equivalent to a transaction over workflow state.
2. **Independent services per feature from day 1:** postponed to avoid operational and consistency complexity without a benchmark.
3. **SDK-specific logic:** rejected for core invariants, to avoid behavior differences between languages.

## Risks and mitigation

- Complexity/scope risk: deliver P1 user stories separately, running contract tests.
- Semantic ambiguity risk: encode reducers and golden fixtures, do not decide via UI alone.
- Crash/redelivery risk: test harness with real failures at checkpoints.
- Security risk: specific pentest and tenant isolation from the first milestone.

## Decisions taken in this feature

- **D42 — A quota is a hard limit judged by an exact count taken under a lock, in the transaction that creates the thing counted.** The security requirement (NFR-009-PERF) forbids deciding a limit from a counter that may be late. The creating transaction takes a transaction-scoped advisory lock on the counted scope (the namespace, then the tenant, always in that order, so the locks cannot deadlock with each other), counts exactly, and refuses with `QUOTA_EXCEEDED` before it inserts. Two replicas racing for the last place serialise on the lock and the second sees the first's row. A refusal is `429`, names the limit and never a value, and is not retryable (waiting does not help; raising the limit or ending a run does). Resources: active runs per namespace and per tenant (child runs count), workflows per namespace, worker sessions per tenant, secrets per namespace. The limit in force is the namespace's own setting, else the tenant-wide one, else the ceiling (the provisional default of G42 unless an operator granted more), and never more than the ceiling (D52); a resource counted per tenant has no namespace level.
- **D43 — A worker identity serves only what a binding names, and the check is made at use.** `worker:execute` makes an identity a worker; a binding (per identity and namespace, a closed grammar: an exact name, `prefix.*` which stops at the dot, or `*`) says which activities it may take. No binding, no registration (fail closed, 403 `NOT_BOUND`, audited). The binding is checked again on every lease-bound report (heartbeat, complete, fail, resolve), on the transaction's own connection, so removing a binding stops a worker that already holds a lease. Removing or narrowing one closes the sessions it no longer covers and releases the attempts they hold to the scheduler, whose fencing makes the revoked worker's late reports stale. Closes G31.
- **D44 — A call that holds a transaction never waits for a second connection from the same pool.** A test of the binding check (twelve concurrent reports against a pool of three) showed that `PgRunStore::begin` loaded an uncached workflow definition through the pool while its transaction held a connection; enough concurrent first requests starve the pool until the acquire timeout. Definitions and bindings are now read on the transaction's own connection, and the test stays as the guard.
- **D45 — Secrets are stored sealed, bound to where they belong, and referenced by name.** AES-256-GCM under a ring of keys (`SAGAT_SECRETS_KEYS`, the first seals, all open); the associated data (tenant, namespace, name, version row, key id) means a ciphertext copied to another secret does not open; the last five versions are kept and `reseal` moves every version to the active key so a retired key can be removed. A definition names secrets on an activity (`secrets: [...]`, names only, at most 16, validated by the IR schema and the codec); a value is never part of a definition, a journal, a lease, an audit record, an error or a `Debug` output. Without a key ring the secret routes do not exist.
- **D46 — Who may use a secret: the role, the secret's own list, and the publisher's standing when the value is asked for.** A workflow that declares a secret can be published only by someone whose role holds `secret:use` and who is on the secret's access list (administrators are not subject to the list); a missing secret and one the publisher may not use get the same answer (403 `SECRET_NOT_USABLE`), so a publisher cannot probe which names exist. The publisher is checked again every time a worker asks for the value, against the role and the list *now*: losing access, leaving the tenant or being demoted stops the next resolution (the edge case "ACL race when renewing a token"), at the cost that a departing author's workflows stop resolving until someone with access republishes them.
- **D47 — The lease is the capability for a secret.** `ResolveSecrets` (worker protocol 1.2, additive) needs the current lease (attempt, generation, token), an identity still bound to the activity and a publisher still allowed; it is all or nothing; and it is audited in the same transaction that reads the values (names and versions, never values), so a value cannot be handed out without a record. A step whose output contains the value of a secret it was given fails for good with `SECRET_IN_OUTPUT` and the output is stored nowhere (the limits of this scan are G41).
- **D48 — Egress is default-deny, and no policy can open the addresses that are never reachable.** One policy per namespace (exact hosts, `*.domain`, CIDR networks, ports, optional plain HTTP); none means nothing is reachable. Loopback, link-local, the cloud metadata addresses, multicast, unspecified and reserved space are refused whatever the policy says (an IPv4 address hidden in IPv6 is judged as that IPv4 address; numbers in disguise are not host names); private space needs an explicit network rule. Features that make outbound requests ask `EgressService`, which also records each refusal with its category and the destination host and port (never the path or the query), once per destination in a window. The audit of a *change* says how many rules changed, not what they are, because they can name internal networks.
- **D49 — The worker API can terminate TLS itself, and refuses to serve secrets in plaintext unless told TLS is in front.** `SAGAT_GRPC_TLS_CERT_FILE` and `_KEY_FILE` (both or neither) serve TLS; `SAGAT_GRPC_TLS_CLIENT_CA_FILE` also requires a client certificate signed by that CA. With a key ring configured outside development and no TLS, the engine refuses to start unless `SAGAT_GRPC_ALLOW_PLAINTEXT_SECRETS=true` says that a mesh or ingress terminates it. The private key and the key ring never print. Closes G27 (identity of the channel against identity of the caller is G44).
- **D50 — Another tenant's resource is a plain not-found, and the battery is driven by the contract.** A resource that exists only in another tenant is a `404` with exactly the body of one that does not exist, and the attempt is audited against the caller's tenant (once per window, off the response path). The cross-tenant battery attacks *every* implemented operation of the OpenAPI document with a valid token of an administrator of another tenant, compares each answer with that of a nonexistent id, and requires the victim's data to be unchanged; an implemented operation without an entry fails the test, so a new endpoint cannot ship unattacked.
- **D51 — Nothing is cached, so nothing needs invalidating.** Quotas, bindings and secret access lists are read from the store on each decision (one indexed read, on the connection the caller already holds where there is one). The sandbox supervisor reads the namespace egress policy immediately before every mediated host call. A committed revocation therefore governs the next policy read; a request already authorized and in flight may finish. FR-009-007's "policy changes with cache invalidation" is satisfied by the absence of the cache; if one is added for speed it must come with a version number that every change bumps.
- **D52 — A tenant's limits are bounded above by a ceiling the platform grants, and only an operator raises it.** Found by the security review: `quota:manage` belongs to the tenant's administrator, who could set `tenant_active_runs` to a billion and so remove the limit meant to protect the other tenants. A limit a tenant sets must now be at most its *ceiling*: the platform default of D42, or what an operator granted that tenant (`quota_ceilings`, written only by `control-plane quota-ceiling`, audited as `system:operator`; the API cannot write it). What is enforced is the minimum of the setting and the ceiling, read in the same query, so lowering a ceiling applies at once to settings made earlier, and with nothing set the whole ceiling is available. The quota view shows the `ceiling`; a `PUT` above it is a 422. Alternatives rejected: a platform-operator role in the API (no operator identity exists outside tenants, and it would widen what a stolen token can do); one global maximum from configuration (cannot sell different capacity to different tenants).
- **D53 — The binding is judged again inside the transaction that stores a session.** Found by the security review: `register` read the binding through the pool and then stored the session, so a revocation committing in between found no session to close and the session outlived it. `create_session` now takes the binding lock that replacing a binding takes (before the session-quota lock, like everywhere: binding, then quota), reads the binding on its own connection and returns "not covered" when it no longer covers the activities. Either the session is stored first and the revocation closes it, or it is judged against the new binding.
- **D54 — A child start refused by a quota fails the parent step, with a code of its own.** Found by the security review: the scheduler treated every quota refusal as the size limit of a tree. They now differ (`CHILD_QUOTA_EXCEEDED` for the namespace and the tenant, `CHILD_LIMIT_EXCEEDED` for the tree), and a workflow can route on either. Waiting for room was considered and rejected: a reservation that keeps waiting stays at the head of the oldest-first queue of `pending_children`, where one tenant's full namespace would stop every other tenant's children from starting; fairness between tenants is feature 010 (G32).
- **D55 — The worker API bounds how long a peer may stay silent, how long a connection lives, and how many an address may hold.** Found by the security review: a socket that never sent a byte, or began a TLS handshake and stopped, held one of the 2048 places for ever. Now a new connection that says nothing is closed after 10 s, an established one silent for 300 s is closed, a TLS handshake has 10 s, a connection is asked to finish and reconnect after 30 min (its in-flight calls have the request timeout), and one address (an IPv6 peer counts as its /64) holds at most 256 connections. All are environment variables. Residual risk: workers behind a single NAT or load balancer share an address, so the cap must be raised to the size of the fleet (or set equal to the global cap); and a peer that sends something every few minutes and answers pings keeps its place until the age limit, bounded by the per-address cap.
- **D56 — Events a caller can repeat at will are written once.** Found by the security review: a worker with a current lease could ask for its secrets as fast as its rate budget allowed, and every call added a row to an append-only table. `secret.resolved` and `secret.denied` are now written once per identical (tenant, actor, action, resource, reason), and the reason names the run, node and attempt, so the trail grows with what happened and not with how often somebody asked. The call is answered every time; the counters (`secrets_handed_out_total`, `secret_resolution_denied_total`) carry the rate.
- **D57 — The output scan covers every kept version and the failure code.** Found by the security review: only the current version was searched, so a value handed out before a rotation could come back in an output; and `fail` took a worker's error code unexamined although a credential fits the characters and length a code may have. Both are closed; a step that reports a secret in its failure code fails for good with `SECRET_IN_OUTPUT`.
- **D58 — The capability ends with the lease; the other smaller findings.** `ResolveSecrets` requires a lease that has not run out by the database clock (reports still accept a late completion until the attempt is reclaimed, to save work). A non-administrator lists only the secrets whose access list names them. `reseal` steps over a version no key opens and reports it at the end, so one bad row stops nobody else's rotation. The control plane, which accepts secret values over plaintext HTTP, needs `SAGAT_API_ALLOW_PLAINTEXT_SECRETS` outside development like the engine. A definition declares at most 128 distinct secrets. `steps (tenant_id, leased_by)` is indexed for the revocation update.
- **D59 — A sandbox denial is durable before it is acknowledged.** The supervisor reports only a closed category (`EGRESS_DISABLED` or one of the six domain denial codes) and a production/test target fenced by tenant, namespace, lease token and attempt identity. The control plane authenticates the runner, validates the current unexpired lease, session and binding, and commits `script.violation` in that transaction. The endpoint is idempotent per target and category. Only a 204 after commit lets the host return `Denied`; a timeout, stale fence or storage failure returns `Failed` and no outbound request is made. Destination, URL, headers and payload never cross this boundary. This guarantees durable evidence for acknowledged supervisor denials, not exactly-once external effects and not observation of raw syscalls that never reached the supervisor.
