`origin/develop` at `70f09435` (release 0.2.0). Nothing in this feature is implemented. The

## 2. External semantics consulted

All sources read on 2026-10-26. They inform the design; they do not prove any platform behaviour.

- **Model Context Protocol, revision 2026-07-28** (current):
  [versioning](https://modelcontextprotocol.io/specification/versioning),
  [changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog),
  [authorization](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization),
  [tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools),
  [tasks extension](https://modelcontextprotocol.io/extensions/tasks). Facts used: the protocol is
  stateless (no `initialize` handshake, no `Mcp-Session-Id`; version and client capabilities travel
  in each request's `_meta`); `server/discover` is mandatory; broken response streams are not
  resumable and a client re-issues the request; `tools/list` may vary by the authorization presented
  but not per connection and should be deterministically ordered, with `ttlMs`/`cacheScope`;
  tool annotations are untrusted unless the server is trusted; tool execution errors are results
  with `isError: true`; servers MUST validate inputs, enforce access control, rate-limit and
  sanitize outputs. Authorization: the server is an OAuth 2.1 resource server, MUST publish
  Protected Resource Metadata (RFC 9728), MUST validate that tokens were issued for it as audience
  (RFC 8707), MUST NOT accept or transit other tokens; tokens never travel in a query string;
  insufficient scope is `403` with `WWW-Authenticate: Bearer error="insufficient_scope"`. Dynamic
  Client Registration is deprecated in favour of Client ID Metadata Documents. The tasks extension
  (`io.modelcontextprotocol/tasks`) returns a task handle (`resultType: "task"`) polled with
  `tasks/get`, with `tasks/cancel`, and statuses `working`, `input_required`, `completed`,
  `failed`, `cancelled`. Roots, Sampling and Logging are deprecated.
- **Anthropic Messages API** (reference cached 2026-10-06, errors page read 2026-10-26):
  [models](https://platform.claude.com/docs/en/about-claude/models/overview),
  [tool use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview),
  [structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs),
  [streaming](https://platform.claude.com/docs/en/build-with-claude/streaming),
  [prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching),
  [errors](https://platform.claude.com/docs/en/api/errors). Facts used: current model ids
  `claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-5-5`; structured output through
  `output_config.format`; forced `tool_choice` (`any`/`tool`) returns `400` on Claude Opus 5.5 and
  Claude Sonnet 5.5, so the adapter must not rely on it; `thinking` blocks must be sent back
  unmodified and the history kept append-only, otherwise a replayed block is rejected; stop reasons
  include `end_turn`, `tool_use`, `max_tokens`, `pause_turn` and `refusal`; usage reports input,
  output, cache-read and cache-write tokens; `429` (with or without `retry-after`), `500`, `504` and
  `529` are transient, `400`/`401`/`403`/`413` are not, and a streaming response can fail after
  `200`; every response carries a `request-id` header; there is no request idempotency key, so a
  re-sent request is generated and billed again. Provider-side server tools, the provider-side MCP
  connector and server-side model fallbacks exist; this feature does not use them (D1293).
- **Temporal durable agents**:
  [OpenAI Agents SDK integration](https://docs.temporal.io/develop/python/integrations/openai-agents)
  and [blog](https://temporal.io/blog/announcing-openai-agents-sdk-integration). Each model call
  is an Activity and the loop runs in Workflow code that is replayed. Sagat keeps the first half
  (every model call is a durable attempt) and replaces the second: the loop is a declarative node
  driven by the engine, so replay-only concepts (determinism of the loop code, patching, sticky
  queues) do not apply.
- **Windmill**: [AI agent steps](https://windmill.dev/docs/core_concepts/ai_agents) (providers as
  resources, script/MCP tools, each tool call its own job, `output_schema`, `max_iterations`,
  newline-delimited stream payloads) and [Windmill MCP](https://windmill.dev/docs/core_concepts/mcp)
  (scripts and flows exposed as tools; the documented URL carries the token as a query parameter).
  Sagat adopts the per-call job model and resource-backed providers, and rejects tokens in URLs,
  which the MCP authorization specification forbids.

## 3. Decisions

| ID | Decision | Why, and the alternative rejected |
|---|---|---|
| D1280 | An `agent` node is an engine-driven loop; every model call and tool call is a durable derived step with lease, fence, heartbeat, retry and journal events; the executor never runs the loop (ADR-0059). | One long activity running the loop loses turns on a crash and hides tool effects from the journal. |
| D1281 | Derived ids `<node>~m<turn>` and `<node>~t<turn>.<call>`, numbered from 1; a tool call's compensation and reconciliation are `<node>~t<turn>.<call>~c` and `~r` (the only two-suffix forms `parse_stored` accepts). Agent node ids are at most 54 characters, so the longest derived id (`~t64.256~c`, ten characters) fits the 64-character node id bound. `agent` only in the root graph and not with `chainPolicy` until scoped agents and transcript handoff are proven (ADR-0036 precedent). *(revised 2026-10-27 after review)* | Scoped identity (ADR-0030) is still gated for nested execution in 014; derived steps need no protocol change for workers serving activity tools. |
| D1282 | Append-only transcript; the first committed result of a model call wins; a lost response is asked again and both requests are charged; provider-opaque blocks (thinking) are replayed verbatim. The rendered request of an attempt is a transient staging blob (upload TTL, counted as an outstanding reservation, deleted when the attempt settles); the transcript is stored once as entries, never re-stored per turn. *(revised 2026-10-27 after review)* | Rewriting history breaks provider replay rules and the journal's authority; re-storing the whole transcript every turn would grow content quadratically. |
| D1283 | Providers and external MCP servers are platform-provided feature-021 resource types (`llm_anthropic`, `llm_openai_compatible`, `llm_aws_bedrock`, `llm_azure_openai`, `mcp_server`) stored in 021's `resources` tables and pinned through `run_resource_bindings`, when 021 is accepted and its types can name the agent runner as executor and declare no `resourceOperation` operations; then 025 creates no catalog tables of its own. If 025 ships first, its `ai_providers*`/`mcp_servers*` tables and `run_ai_bindings` are moved into 021's tables by one migration that keeps ids, revisions and pins and then drops the 025 tables; the two catalogs never coexist (coordinator C22, O1282). *(revised 2026-10-27 after review)* | Waiting blocks 025; duplicate catalogs are debt; credentials for model providers must not reach the integration runner. |
| D1284 | Kinds `anthropic`, `openai-compatible` (Chat Completions with tools and JSON-schema format), `aws-bedrock` (SigV4), `azure-openai`; text and JSON only. | Other modalities and providers are additive kinds with their own token bound and fixture. |
| D1285 | A revision lists allowed models with optional declared prices; cost is computed only from them and is an estimate; a cost budget on an unpriced model is refused. | The platform cannot know negotiated prices. |
| D1286 | Every model-call attempt reserves its conservative bound (rendered request bytes as the text-token bound plus `maxOutputTokens`, and the estimated cost) against the agent's budgets and the namespace's daily row in the transaction that grants its lease; a reservation that does not fit fails the derived step with `AI_BUDGET_EXHAUSTED` before any lease reaches a runner (precedent: the `RUN_DATA_LIMIT` preflight in the claim). The scheduling transaction pre-checks that one reservation would fit. Completion settles reported usage; a provider error response releases the reservation (G1294); a lost response, timeout or lease expiry converts it to charged-unknown. G1284 still applies to the bound. *(revised 2026-10-27 after review)* | Reserving per turn let retries and in-flight calls overshoot budgets and the daily quota. |
| D1287 | Exhaustion fails the step with non-retryable `AI_BUDGET_EXHAUSTED`; no partial result. | A partial answer resembling validated output is unsafe downstream. |
| D1288 | `instructions` and `prompt` are literals pinned in the version; run data enters only through named `context` expressions evaluated server-side without secret capability. | Interpolating data into the system prompt mixes untrusted input with instructions and breaks caching. |
| D1289 | A provider revision MUST declare `maxPromptClassification` and an external MCP server revision MUST declare `maxArgumentClassification` (`public`/`internal`/`pii`; `secret` is not a value). Publication computes the agent's transcript level (D1319) and refuses it above the provider's ceiling and refuses an `mcp` tool whose server ceiling is below it. A value without a carrier counts as `pii` (ADR-0033 decision 2); at run time a value that does not validate against its carrier is not sent. Tool results use the target's output carrier or the tool's own closed `outputSchema`. (O1280) *(revised 2026-10-27 after review)* | Data leaves to two kinds of third party, the model provider and the MCP server; a non-validating value may hide a `secret` field. |
| D1290 | The transcript is `pii` as a whole; the only reader is an audited endpoint with the feature-016 `pii` audience (`run:read`, `payload:read-internal`, the namespace reveal grant); each read is a `payload.pii_revealed` audit that never collapses. The same audience applies to the token stream through FR-026-018. | Field-level classification of model text is impossible; one audience for transcript and stream avoids a second gate that 026 would not enforce. |
| D1291 | Agent output `{result, usage, stopReason, turns, toolCalls}` with a generated carrier: every `result` field's effective level is at least the transcript level (D1319); a looser author annotation is refused at publication (`CLASSIFICATION_LOOSENED`); metadata fields are `internal`. *(revised 2026-10-27 after review)* | A model can copy anything that entered its transcript into any output field; trusting a `public` annotation would relabel `pii` (review B4). |
| D1292 | A tool's `inputSchema` is a carrier only for the approval view of that tool call, with every field at least the transcript level; a looser annotation is refused. A `child` tool's arguments become the child's input, so the child version's `inputSchema` levels must also be at least the transcript level. *(revised 2026-10-27 after review)* | Approvers must see what they approve, and model-written input must not be relabelled. |
| D1293 | Always validate the final answer; use native constraints where declared, never forced tool choice (rejected by current Claude models); bounded repair turns; no provider server tools, provider MCP connector or server-side fallback. | Provider guarantees differ; provider-side tools bypass egress, audit and durability. |
| D1294 | `modelOptions` is `effort` and `maxOutputTokens` only; no sampling knobs; thinking at provider default, never streamed; prompt caching on by default for `anthropic`, accounted from usage. | Fewer provider `400`s; caching cuts the cost of resending the transcript. |
| D1295 | Tool kinds `activity`, `script`, `database` (query; `execute` only with approval), `operation` (a 021 `resourceOperation` run by its integration runner, ADR-0055), `child`, `mcp`; a sub-agent is a child workflow containing an agent. | Each kind keeps its executor's isolation; no new path for user code. |
| D1296 | Tool key `agent:{runId}:{node}:{turn}:{call}`; `read` retries; unknown `write` outcome → `reconcileWith` or manual review; default `write`. A `write` tool MUST declare `approval` or the explicit acknowledgement `approval: "none"`; an exposure (MCP) or a feature-026 public link MUST refuse a version containing an acknowledged unattended write tool; `operation` tools always need `approval` (G1293). *(revised 2026-10-27 after review)* | ADR-0004; a manipulated model must not reach an unattended effect from an anonymous or remote caller (review S2). |
| D1297 | Tool approvals reuse 014 semantics and `approval_requests` via owner kind `AGENT_TOOL_CALL`; `refuse` or `fail` on reject/expiry; decisions through the existing endpoint. | A second mechanism would fork decision-time authorization and the expiry race. |
| D1298 | `apps/agent-runner`, role `agent-runner` (`worker:execute`, `ai:execute`), reserved activities `sagat.ai.model`, `sagat.ai.mcp`, `sagat.ai.probe`, `sagat.ai.mcp-refresh`, next free protocol minor (provisionally 1.7, G1280); no platform DB URL, OpenBao token or signing key. AI concurrency is the count of live leases of these activities, read under a namespace and tenant lock in the claim transaction (017 precedent), so completion and lease expiry release it without a counter. *(revised 2026-10-27 after review)* | ADR-0013/0035 isolation and the placement rule written by 021 in ADR-0055 (coordinator C3 (a)): a request whose content a tenant authored in a workflow (model prompts, tool calls) is sent only by a managed executor holding only that attempt's capability; a counter would leak capacity when a runner dies. |
| D1299 | Two-phase `ResolveModelCall`/`ResolveMcpCall` (fences, OpenBao I/O outside the run transaction, fences again with audit and metadata-only pin); never a deployment cloud identity for tenant accounts; adapters MUST use explicit static credential providers and MUST NOT use SDK default credential chains or instance-metadata lookups. *(revised 2026-10-27 after review)* | A shared deployment identity is a cross-tenant credential; default chains fetch metadata credentials with their own HTTP client, outside the egress guard. |
| D1300 | Guarded egress with namespace policy; private destinations need the ADR-0035 runner policy; add a bounded incremental reader for SSE. | Keeps SSRF and metadata denial. |
| D1301 | The MCP server exposes nothing by default; an exposure has revisions, one target, a closed projection with `disclosure: "declared-mcp-result-v1"` and `maxResultClassification` (ADR-0060). | ADR-0031 precedent: disclosure is declared, never implied. |
| D1302 | MCP 2026-07-28 plus stateless 2025-11-25 compatibility (no `Mcp-Session-Id`); tools, `server/discover`, tasks extension; no sampling, roots, logging, resources, prompts. | Smallest surface serving current and previous clients. |
| D1303 | OAuth tokens whose only audience is the configured canonical MCP URI, with Protected Resource Metadata answered identically for every well-formed namespace id; REST refuses any token whose audience contains an MCP URI; or scoped MCP tokens (hashed, expiring, revocable, minter's current rights ∩ scope). Header only; no passthrough. *(revised 2026-10-27 after review)* | A multi-audience token would be replayable between REST and MCP; a namespace-specific 404 would be an existence oracle. |
| D1304 | A call is an ordinary durable admission, deduplicated by optional `_meta` `sagat-octopus-orchestrator.io/idempotencyKey`; otherwise each call is a new run, documented. The bounded wait reuses 026 `executeRun` semantics (FR-026-007, FR-026-009) when available. Non-terminal after the wait: task or run handle. `tasks/get` and `tasks/cancel` re-check `mcp:call`, token scope, exposure state and result-level rights on every call. *(revised 2026-10-27 after review)* | MCP has no idempotency field; a task handle is a name, not a capability. |
| D1305 | MCP client: server resource with revisions; explicit durable refresh stores immutable snapshots; publication pins one; drift → `AI_TOOL_CHANGED`; descriptions untrusted; no client `input_required`/tasks support. | Defends against definitions changing after review. |
| D1306 | MCP client auth: none, static bearer secret, OAuth client credentials with resource indicator. For OAuth, the issuer and token endpoint are recorded in the server revision by an `ai:manage` holder (proposed by a refresh, confirmed by saving); the client secret is sent only to that endpoint; advertised metadata that differs is audited (`mcp.oauth_metadata_changed`) and calls are refused until the revision is updated. No user-delegated flows (G1288). *(revised 2026-10-27 after review)* | A server could otherwise redirect the client secret to a token endpoint of its choice (review S1). |
| D1307 | Token streaming only through 026 Workflow Streams on the reserved channel `sagat.agent.tokens` with `AppendStreamEvents` under the model call's lease (FR-026-013, FR-026-014). The agent's reserved-channel budget per run is the effective `maxTurns` × the per-call event and byte caps, clamped to 026's per-run hard ceiling for reserved channels, counted apart from author channels; deltas are coalesced; 026 marks superseded attempts (FR-026-016, G1295) and projects events per reader (FR-026-018); without 026 publication refuses `stream.tokens`. *(revised 2026-10-27 after review)* | Per-call caps alone let multi-turn agents exhaust the run's stream budget after two or three turns (review S6). |
| D1308 | The assistant is an internal durable run (origin `AUTHORING_ASSISTANT`) without tools whose validated proposal is applied only by the user's draft write; draft documents and the request text count as `internal`, so the assistant provider must declare at least `internal`. *(revised 2026-10-27 after review)* | Publishing would bypass ADR-0018 approval; draft content is data sent to a third party too. |
| D1309 | `apps/dev-model-provider` (development only) speaks the adapters' Anthropic and OpenAI-compatible subsets and hosts a test MCP server; real-provider smoke tests are opt-in. | Owner decision 2026-10-17 item 5; ADR-0019. |
| D1310 | Rerun re-executes the agent from the start with new costs. A 018 reset point inside an open agent loop (after `agent.started`, before `agent.finished` of the same step) is refused; a finished agent step is re-materialized by the reset transaction without repeating any call (D1635). *(revised 2026-10-27 after review)* | ADR-0039; terminal runs never return to running; an open loop cannot be resumed from a journal prefix without its in-flight calls. |
| D1311 | Approval waits count toward the agent deadline; approval timeouts are clamped to the remaining wall time. | One deadline to reason about. |
| D1312 | New permissions `ai:manage`, `ai:use`, `ai:execute`, `mcp:expose`, `mcp:call`, `mcp:token:manage`; machine role `agent-runner` (O1281). Transcript reading reuses the 016 `pii` audience (D1290). The initiator checked for `ai:use` is the human starter; for MCP-admitted runs the OAuth subject or the scoped token's minter; for 026 public-link runs the link's creating principal, re-checked at admission; when none can be determined admission fails. *(revised 2026-10-27 after review)* | Separates management, use, exposure and machine execution, as 017 did; no anonymous or remote caller inherits AI use. |
| D1313 | In a saga region, completed tool calls compensate in reverse completion order; a `write` tool without compensation is irreversible (`PARTIAL`). | FR-003-002 and ADR-0005 without a new saga rule. |
| D1314 | The provider probe lists models and never generates tokens. | Generation costs money and proves nothing more. |
| D1315 | Script and operation exposures wait for 022 standalone steps; workflow exposures first. | 022 owns standalone execution. |
| D1316 | `tools/list` returns callable exposures only, in name order, `cacheScope: "private"`; `tools/call` on an exposure the caller cannot call (in scope but lacking `run:start` or the result-level rights) answers "Unknown tool", like an absent one, and audits the denial. *(revised 2026-10-27 after review)* | Allowed by MCP; a different answer would reveal hidden tools. |
| D1317 | External MCP results keep text and structured content only; other content is dropped with a truncation flag; bounded and secret-scanned. | Text-only modality; bounded untrusted content. |
| D1318 | No new `Error.code`; new `details.reason` values and durable failure codes with remediation rows. | Exhaustive SDK parsers keep working (014). |
| D1319 | **Transcript level.** For each agent node, publication computes the transcript level: the strictest of `internal` (instructions, prompt and tool descriptions), the levels of every carrier path a context expression references, and the result carrier level of every declared tool (no carrier: `pii`; MCP results without an author `outputSchema`: `pii`). Model-written content can contain anything at that level, so it bounds the provider ceiling from below (D1289), the MCP argument ceiling (D1289), the floor of `result` fields (D1291), of approval-view tool inputs and child inputs (D1292). *(added 2026-10-27 after review B1–B4)* | One static rule, checkable at publication, replaces trust in author annotations for model-written values. |
| D1635 | **Reset rules (coordinator C1).** 025 registers in 018's reset-rule registry (`specs/018-schedules-bulk-operations/contracts/journal-and-events.md`): `agent.started`, `agent.turn_scheduled`, `agent.turn_completed`, `agent.tool_planned`, `agent.tool_refused`, `agent.tool_completed`, `agent.repair_scheduled` and `agent.budget_exhausted` are `REFUSE` while their agent step is open (no `agent.finished` in the prefix), which covers tool-call approval events of that step; once `agent.finished` is in the prefix, all of them and `agent.finished` are `REMATERIALIZE`: the reset transaction copies the step's `agent_steps`, `agent_turns`, `agent_tool_calls` and transcript entries into the new run, referencing the same retained payloads (charged to the new run), and repeats no model or tool call and charges no budget or daily usage. | An open loop has calls in flight whose results the new run could not receive; a finished one is plain history. |
| D1636 | **Encoded fields (coordinator C7).** 025 registers its positions in 031's registry (`specs/031-client-side-encryption/contracts/workflow-encoding.md`) and uses 031's codes: `agent.context.*` and `agent.tools[].result` are inspection positions (`ENCODING_READ_BY_EXPRESSION`); a tool whose result carrier holds an encoded location and has no projection avoiding it is refused the same way (its whole result would enter the transcript); a `child` tool input fed by model-written plaintext into an encoded location is `ENCODING_CARRIAGE_MISMATCH`; an agent `outputSchema` or tool `inputSchema` that declares an encoded location is `ENCODING_NOT_PRODUCIBLE` (the platform never holds the customer's keys); an MCP exposure projection is an inspection position. No 025-specific encryption code exists. | Encrypted values are opaque to the server and cannot be sent to a model or written by one. |
| D1637 | **`pii` egress (coordinator C9, 020's O1081 rule).** Setting `maxPromptClassification: pii` on a provider or `maxArgumentClassification: pii` on an MCP server requires the saving administrator to hold the namespace reveal grant; that grant is rechecked at each model-call or MCP-call resolution whose transcript level is `pii`; revocation pauses the provider or server (`AI_CAPABILITY_UNAVAILABLE` until revised); each such attempt is audited `ai.pii_egress`; `secret` never leaves. | One rule for every place `pii` leaves the platform (sinks, archives, providers, MCP servers, channels, codec endpoints), as ADR-0033 refined by 020's O1081 proposes. |
| D1638 | **Shared registries and catalogs (coordinator C8, C10, C11, C13).** Transcripts, tool inputs and results, agent outputs and request staging blobs are content stores in 020's content-store registry, purged with the run's content under 020.
