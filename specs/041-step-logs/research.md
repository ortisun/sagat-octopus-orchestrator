# Research: step logs per run (design 041)

Registers of the design [docs/designs/041-step-logs.md](../../docs/designs/041-step-logs.md). Append-only:
numbers are never reused or renumbered; a gap is closed by evidence, not by deletion.

## Decisions

The owner questions these rest on were all answered as recommended (OD-2026-11-13-14).

| ID | Date | Decision | Why |
|---|---|---|---|
| D041-001 | 2026-11-13 | A step log is a diagnostic record beside the journal, never execution state | The journal is never purged and is written under the run lock; log volume there would slow replay and the hot path |
| D041-002 | 2026-11-13 | Transport is a new unary RPC, `AppendStepLogs`, in worker protocol minor 1.7 | A field on `Heartbeat` ties a batch to the lease's liveness; one on `CompleteStep` adds statements to the budgeted completion |
| D041-003 | 2026-11-13 | A batch is accepted only while its attempt holds the lease, checked by a read of `steps` without a lock | The fence that already exists; a lock would put ingest in the queue of leases and completions |
| D041-004 | 2026-11-13 | A record's identity is (attempt, generation, sequence); the stream key includes the generation | Two holders of one attempt number can then never collide, whatever recovery does |
| D041-005 | 2026-11-13 | The log tables have no foreign key to `runs` or `steps` | The key's `KEY SHARE` lock conflicts with the engine's `FOR UPDATE` on the run row |
| D041-006 | 2026-11-13 | Lines are read in (storing transaction id, row id) order below the snapshot's `xmin` horizon | A page is final and a tail never skips, without a per-run sequence taken under the run lock |
| D041-007 | 2026-11-13 | The table is not partitioned; purge is by batched `DELETE` | Dropping a partition does not fire the quota triggers of ADR-0027, and retention differs per tenant |
| D041-008 | 2026-11-13 | Secret values are removed by the SDK, by value; the server applies the shape and field-name rules | Only the worker process holds the values; a server read of the secrets per batch would be a disclosure to audit each time |
| D041-009 | 2026-11-13 | The existing `/runs/{runId}/stream` does not carry log lines | It has one resume point (the projection sequence) and is granted by `run:read` |
| D041-010 | 2026-11-13 | The Rust SDK gains an activity logger in this feature | `sdks/SPEC.md` §6.3 promises one and capture needs it |
| D041-011 | 2026-11-13 | Sequences at and above 2^62 belong to the server's markers | A marker then never collides with a worker's record |
| D041-012 | 2026-11-13 | The streams' counters are served by a route of their own, not added to `/attempts` | The OpenAPI digest pins existing operations byte for byte |
| D041-013 | 2026-11-13 | The ingest does not take the tenant's `tenant_retained_usage` row before its commit unless usage plus the batch is within 2 MiB of the limit; then it takes it as the last statement before the insert, under a 200 ms lock timeout. Refines how D041-003's transaction treats quota | `sagat_quota_lock_log_usage` holds the row a completion with output needs to commit; the commit-time finalizer already enforces the limit exactly (review: architecture B1, correctness M3, security M2) |
| D041-014 | 2026-11-13 | Capture lives in the per-attempt logger object of each SDK; nothing is attached to a shared logger. Redaction uses the union of the secret values held by every attempt in flight in the process | Python's `_TaskLog` adapts the worker-wide logger, so a handler there sees every attempt (review: security B1, architecture M4) |
| D041-015 | 2026-11-13 | The ingest makes every check a report makes short of the run lock: `worker:execute`, not the database-runner or runner role, membership, activity binding, session (subject and minor, through a session token added to the request) and a lease that is `LEASED` or `RUNNING`, unexpired, on a run neither finished nor stopping. Extends D041-003 | A lease-token match alone survives revocation (review: security M1, N1) |
| D041-016 | 2026-11-13 | The server scrubs in the application, before sizing, with both existing scrubbers (`sagat_domain::scripts` and `sagat_telemetry::redact` shapes, without its 2,048-character cut) and one placeholder `[REDACTED]`; the SDK redacts keys, numbers, exceptions and language context as well as messages. Extends D041-008 | Review: security M3, M4, architecture N1 |
| D041-017 | 2026-11-13 | Order within a batch: lock the stream, drop known sequences, fold `DROPPED` ranges, then the attempt, run and tenant allowances, insert with `RETURNING`, counters from the returned rows. Fields are stored as canonical JSON `text` so that the size computed in Rust equals what `sagat_quota_measure` measures | Review: correctness M2, security N7 |
| D041-018 | 2026-11-13 | A `DROPPED` marker names the first and last sequence it covers and carries no count; the server counts the unseen sequences of the range, saturating and clamped at the attempt ceiling. `last_sequence` (worker range) and `next_marker_sequence` (server range, from 2^62) are separate columns. Markers hold no log-classified bytes. Run-ceiling and tenant-quota drops are recorded only on the stream row. Batches after `final` are refused. Refines D041-011 | Review: security M7, correctness M5, N1, N6, N7 |
| D041-019 | 2026-11-13 | The ingest's first statement assigns its transaction id; the tail ends only when the snapshot horizon has passed the `xmax` seen at the first terminal poll and a further page is empty. The horizon is computed in the statement that reads, on `xid8`. Refines D041-006 | Otherwise a batch that saw the lease live can commit after `end` (review: correctness M1, architecture M1, correctness N3) |
| D041-020 | 2026-11-13 | One lock order for step-log writers: secrets lock and membership, stream, run usage, content fence, log fence, tenant usage row. The script marker locks only its own `source = script` stream and does not charge `run_log_usage` | Review: correctness M4, architecture M2 |
| D041-021 | 2026-11-13 | The script marker takes its generation from the `step.leased` event `record_execution` already reads; generation and instance path are nullable for `source = script` | `record_execution` finds the step by (tenant, run, node) and has no instance path (review: architecture M3) |
| D041-022 | 2026-11-13 | Ordinary SDKs offer 1.7, which carries 1.6's `ResolveDatabase` on the wire; the server refuses it without `database:execute`, and `sdks/SPEC.md` §7.1 says so | Review: architecture M5 |
| D041-023 | 2026-11-13 | The lock and no-foreign-key tests live in `tests/integration/claim-transition-efficiency/`, which the selector picks for every `crates/infra-postgres/` change | Review: architecture M6, correctness M6 |
| D041-024 | 2026-11-13 | Alerts fire on shedding and purge backlog only; ceiling drops are the customer's code and are shown on the run | Review: architecture M7 |
| D041-025 | 2026-11-13 | An admin-only, audited `DELETE /runs/{runId}/logs` (`run:logs:delete`, `run.logs_purged`); expiry is computed at purge time from the last line and the retention in force | Review: security M8 |
| D041-026 | 2026-11-13 | In a namespace whose published versions carry a classification annotation (`namespaces.has_classified_schemas`, set at publication and backfilled), reading step logs also needs the PII reveal grant; a script execution's `log` is read under the same rule | Owner, OD-2026-11-13-18 (O041-012, O041-013) |
| D041-027 | 2026-11-13 | `AppendStepLogs` has its own admission class and permits with a per-tenant sub-cap; capture defaults to off until the purge pass is merged; a separate switch turns the read routes off | Review: architecture B1, N8, security N8 |
| D041-028 | 2026-11-15 | Records have no kind: the `DROPPED` record is removed. The server counts every gap between `last_sequence` and a batch's high mark (the final batch carries `highest_sequence`), as dropped by the worker below `ceiling_sequence` and by the server above it, saturating at 2^53. A ceiling answers `FINAL_ONLY` (send no more records, still send the empty final batch); `last_sequence` takes `GREATEST`. Supersedes D041-018 for the drop count and refines D041-011 | Sequence gaps already prove each drop; the old `STOP_ATTEMPT` at a ceiling stopped the final batch, so SC-041-002 could not hold (consolidated A-M5; correctness r1-M5, M4, N4, N5 of 2026-11-15) |
| D041-029 | 2026-11-15 | The ingest never takes the tenant's `tenant_retained_usage` row before its commit: no 2 MiB band and no locking path. Over the tenant allowance (by the unlocked read, or the finalizer's raise at commit) the batch stores nothing, the stream records `tenant_quota`, and the answer is `FINAL_ONLY`. ADR-0027's rule of keeping what fits is read as applying to the terminal reports it was written for. Supersedes D041-013 | The locking path held the row a completion needs and made the Goals false (consolidated A-M2) |
| D041-030 | 2026-11-15 | No step-log row is written for a script step; `listRunLogStreams` with `source = script` lists the run's `script_executions`, paged on its own. Supersedes D041-021 and the script half of D041-020 | The marker needed a write path, a nullable key and a lock-order exception to point at a row the read side can list (consolidated A-B3) |
| D041-031 | 2026-11-15 | The end of a read follows D1958 of feature 018: the first read that sees the run finished takes `end = pg_current_xact_id()` and carries it in the cursor; `complete` (and the tail's `end`) needs `pg_snapshot_xmin > end` in the reading statement and an empty page. Supersedes the end rule of D041-019 | A snapshot's `xmax` is the last completed id plus one, so `xmin >= xmax` passes while a transaction with that id is open (consolidated A-M1) |
| D041-032 | 2026-11-15 | Ingest order: id, lease read without a lock matching the request's run, instance path and node (the row, never the request, gives run, namespace, node and path), session by (tenant, id, that namespace, subject, token hash, unexpired, minor >= 7) and the namespace's policy, stream row, plan, run usage row, unlocked tenant read, then the authority checks last before the insert (binding lock, `first_uncovered` against `steps.activity`, `current_worker_authorized` with an argument naming the refused roles, so `share_secrets_lock` keeps its one caller). Lock order: stream, run usage, binding, secrets lock, membership, then the finalizer's fences and tenant row. Refines D041-015 and supersedes the order of D041-020 | The session and binding checks need the lease's namespace and activity; locks held to commit are taken last; a lease must not write into another run (consolidated A-M14; security r1-M1, N6, N9 and re-audit M1; correctness M2, M3, N9) |
| D041-033 | 2026-11-15 | `StepLogPolicy` carries only `enabled`, derived at registration from the deployment switch and the namespace's `step_log_attempt_records` (0 turns capture off) and re-read per batch; the SDK's buffer, flush and batch numbers are constants of `sdks/SPEC.md` | Each policy field would be a permanent 1.7 contract; a session belongs to one namespace (consolidated A-M6) |
| D041-034 | 2026-11-15 | Admission is one `Class::Logs` with its own counter outside `Shared.in_flight` (`SAGAT_GRPC_MAX_LOG_CALLS`, a quarter of the pool by default) and a per-tenant ticket set taken without waiting after authentication (4 per replica); no semaphore below the pool. Refines D041-027 | Admission runs before authentication; a Logs call must not lower discovery capacity (consolidated A-M15; security M5) |
| D041-035 | 2026-11-15 | The cursor is plain `base64url` JSON with the run id, the position (`stored_xid`, `sequence`) and the end horizon; there is no row identity on lines, so none reaches a cursor; a cursor of another run is refused 400; the stream's public id is a UUID | Every other cursor of the API is plain; sealing needed key management nothing else has; the identity showed every tenant's line volume (consolidated A-M16; security M6 and re-audit N6) |
| D041-036 | 2026-11-15 | `run.logs_read` is written by `insert_audit` with `collapses_repeats` and a 300-second `repeat_window`, under its advisory lock on (tenant, actor, action, resource); the record holds no filter | The facility exists and races are already serialised there (consolidated A-M17) |
| D041-037 | 2026-11-15 | A classified namespace is a row of the insert-only `classified_namespaces`, written by an `AFTER INSERT` trigger on `workflow_versions` when the canonical JSON holds the text `"x-sagat-classification"`, and once by the migration for existing versions. Supersedes the `namespaces.has_classified_schemas` column of D041-026 | An `UPDATE` grant on `namespaces` widens the runtime role; recording in the binary fails open for an old or rolled-back binary, which the instance registry cannot see (consolidated A-M12; security M3 and re-audit M2; architecture M5 and re-audit M1) |
| D041-038 | 2026-11-15 | The purge marks expired streams (`removed_at`, after which no line is served and no batch is stored), then deletes at most 500 lines per transaction and sets `purged_at` when none is left; it does not skip a leased stream; the delete route sets `deleted_at` and `removed_at` | A 5,000-row purge held the tenant row; a late batch, or one between two purge transactions, could leave rows nothing deletes (consolidated A-M10; architecture M2; correctness M5 and re-audit M3; security N5) |
| D041-039 | 2026-11-15 | The ingest's rules are a pure `plan_batch` and `validate_batch` in `crates/domain/src/step_logs.rs` with property tests; the port `StepLogTx` only reads and writes | Rules in the adapter could drift from the report fence and be tested only against PostgreSQL (architecture M6 of 2026-11-15) |
| D041-040 | 2026-11-15 | `ScriptExecution.log` stays required: a withheld log is `""` with `logTruncated` false and `logWithheld: true`, and the listing shows `logTruncated` false to the same caller | The schema change becomes additive and the size class is no longer disclosed (architecture M4, security M4 of 2026-11-15) |
| D041-041 | 2026-11-15 | The tail re-checks the reader's right and grant every `StreamLimits::recheck` (30 s), as the graph stream; the window is stated in FR-041-012 | A check per poll costs a membership lock twice a second per tail (consolidated A-N3) |
| D041-042 | 2026-11-15 | A line has an `exception` text of its own (8 KiB, `log`); each SDK gains the logger calls section 6 of the design lists (trace, fields and exceptions where missing; a logger in Rust); capture does not depend on the host's enabled check | Java had no fields or `Throwable`, three SDKs had no trace, so FR-041-007 could not be met (consolidated A-B2) |
| D041-043 | 2026-11-15 | A spike (T041-31) on a scratch schema runs before the migration merges, with a stated workload and pass rule, and has one contingency: stop, change the design, review again. The grouped commit is no longer the named fallback | The old spike ran after the schema was fixed, and the grouped commit lengthens each hold of the tenant row (consolidated A-M3) |
| D041-044 | 2026-11-15 | New operations are `x-planned: '041'` until the task that serves them; the digest test approves both tags for 041 | The cross-tenant battery attacks every `x-implemented` operation (consolidated A-M19) |
| D041-045 | 2026-11-15 | The server reaches the existing shapes through `sagat_telemetry::redact::scrub_shapes_with(text, placeholder)` and a public `sagat_domain::scripts::redact_credentials`; a field under a sensitive name becomes `[REDACTED]` whatever its type | `scrub_shapes` and `redact_credentials` were private and `scrub` cuts at 2,048 characters (consolidated A-M21) |
| D041-046 | 2026-11-15 | `fields` is canonical JSON as data-model.md §5 defines it, and a number's decimal text is the form of ECMAScript `Number::toString` in every SDK and on the server | Redacting each language's own decimal text leaked numeric secrets (security r1-M4; consolidated A-N14) |
| D041-047 | 2026-11-15 | Schema detail, grants, quota resources and metric names live in `specs/041-step-logs/data-model.md`, and the contract in `specs/041-step-logs/contracts.md`; the quota triggers are created on `step_log_lines` only | The design keeps invariants; the manifest requires triggers only on tables with `log` or `content` columns (consolidated A-M7, A-M9, A-B1) |
| D041-048 | 2026-11-15 | Tests on PostgreSQL 18 use a `SAGAT_TEST_POSTGRES_TAG` override of the test support and a CI step, and the horizon tests run in a container of their own; T041-6 creates `integration_step_logs`; a selector rule for step-log code waits for O041-022 | The support pins `postgres:16-alpine`; the horizon is cluster-wide; the constitution's CI gate allows only the suites it names (consolidated A-M24, A-M25; re-audit) |
| D041-049 | 2026-11-15 | A stream keeps the `step_log_retention_days` of its namespace at creation; its `expires_at` is its last batch's server time plus that retention. A lowered retention applies to new streams. Supersedes the purge-time expiry of D041-025 | ADR-0027 forbids retroactive deletion by a lowered policy; the delete route removes lines early (design critic re-audit C) |
| D041-050 | 2026-11-15 | An answer the ingest decides before its authority checks (session, capture off, removed, final recorded, tenant quota) is given only after those checks pass, so a revoked caller learns only `AUTHORITY`; the transaction after the finalizer's raise repeats the checks and re-plans under the stream lock with a tenant allowance of 0; the cross-tenant audit is written outside the ingest transaction | A revoked caller could learn of a delete; the second transaction could count records twice or not at all (security re-audit N3, N8; correctness re-audit M1) |
| D041-051 | 2026-11-15 | The end horizon is taken in a short transaction of its own, begun after the read saw the run finished; an `end` in a cursor of a run that is not finished is ignored | The read transaction may already hold an id from the audit insert, assigned before it saw the run finished; a plain cursor can be forged (correctness re-audit M2, design critic re-audit A, architecture re-audit N10) |
| D041-052 | 2026-11-15 | `SAGAT_GRPC_MAX_LOG_CALLS` defaults to a quarter of the database pool and the per-tenant tickets to half of it; a test holds lease p99 within 10% while the Logs class is full | The cap is what keeps ingest from holding the connections lease calls need (design critic re-audit E, architecture re-audit N9) |
